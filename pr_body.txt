🧨 **The Trigger:**
A classic re-entrancy deadlock. The framework executes user-provided code (closures) for Queries, Updates, and Side Effects. If a user calls back into the framework during one of these closures (e.g. attempting to register a new query while executing an existing one, or nesting a `ctx.side_effect`), the framework attempts to re-acquire a `std::sync::Mutex` that the thread already holds, causing a total halt.

📉 **The Stack Trace:**
(Typical deadlock timeout failure)
```
thread 'test_side_effect_reentrant_deadlock' (63552) panicked at autumn-harvest/tests/havoc_tests.rs:143:5:
The side effect should have deadlocked!
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

🧪 **Reproduction:**
Run the new tests added in `autumn-harvest/tests/havoc_tests.rs`:
```rust
ctx.register_query("deadlock", move || {
    ctx_clone.register_query("new", || json!({"status": "new"})); // Deadlocks on query_registry
    json!({})
});
```

😈 **Comment:**
"You assumed your users would be polite enough not to recursively call into the context. You were wrong. I just deadlocked your entire thread pool by asking the context a question about itself. Fixed it by extracting the handler and dropping the lock *before* execution."
