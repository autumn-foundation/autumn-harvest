**`harvest det-check` CLI — the runnable front door for `det_check`, plus one first-party hop of transitive reachability (issue #778).** Turns the already-shipped `det_check` engine (DET001–DET011, `harvest-suppress`, `DetCheckReport`, `has_hard_blockers`) — which had **no runnable front door** — into a governance gate authors actually invoke, and closes the exact coverage gap #386 punted: a non-deterministic call (`chrono::Utc::now()`, `rand::random()`, …) factored out of a `#[workflow]` body into a **first-party helper function the body calls directly** used to sail past `cargo build`, the macro lint, and the body scanner, only to DLQ post-deploy. **Read-only source analysis: no `WorkflowEvent` variant, no event-schema change, no migration, no change to the `::autumn_harvest::` macro-path contract, no runtime code touched.** *(PR #1055.)*

**Engine (`autumn-harvest/src/det_check.rs`):** (a) **serde (AC2)** — `DetSeverity` (with `#[serde(rename_all = "lowercase")]` → `"error"`/`"warning"`), `DetLocation`, `DetFinding`, `DetSuppression`, and `DetCheckReport` now derive `serde::Serialize` for `--format json`. (b) **`DetLocation.col` (AC1)** — a new `pub col: u32` (always `> 0`), computed as the 1-based character column of the matched substring in the raw source line for the substring-table rules (DET001–DET009, DET011); the bespoke DET010 pass and any offset-less site report `1`. (c) **`DetFinding.via_helper: Option<String>` (AC4)** — `#[serde(default, skip_serializing_if)]`; `None` for a direct-in-body finding (`workflow_name = Some(wf)`, unchanged), `Some(helper)` for a transitive finding (`workflow_name = Some(entry_point)`, `location` = the offending line inside the helper). (d) **Transitive reachability** — the old `#[workflow]`-only `extract_workflow_bodies` is generalized to `extract_all_functions`, which walks each file tracking brace depth and captures every **top-level** (file-depth-0) `fn` definition with `is_workflow`/`is_activity` flags and an owned body (so a cross-file index can outlive per-file line buffers); methods inside `impl`/`trait` blocks (depth > 0) are never captured. `check_source` resolves one-hop calls within one file; `check_dir` first builds a first-party function index across every `*.rs` in the tree, then follows one hop of **direct free-function calls** (`helper(` — never `x.helper(` method calls, never `m::helper(` path-qualified calls, never identifier-continuation) from each `#[workflow]` body into plain (non-workflow, non-activity) helpers, scans those helper bodies with the *same* per-body analysis (all rules, suppressions included), and attributes findings to the entry point via `via_helper`. **One hop only** (workflow → A → B is not followed into B); **`#[activity]` callees are skipped** (an activity legitimately reading the clock reached from a workflow is not flagged); a helper **name defined by more than one plain helper is ambiguous and never resolved**, so an ambiguous resolution can never introduce a false positive. Findings are deduped by `(rule_id, entry-workflow, file, line)`. `check_dir` now also **skips `target` and hidden directories** so a scan of a repo root stays fast and never lints generated code.

**CLI (`autumn-harvest-cli`):** new `harvest det-check [PATHS...]` subcommand (default `.`). Local `--format text|json` flag (distinct from the global `--output`), `--deny-warnings`, and `--list-suppressions`. Handled entirely in-process before the HTTP execute path (mirrors the Tui early-return; `api_request()` for it is `unreachable!`). Text mode prints `file:line:col DETxxx  (safe alternative: …)` per finding — with `[in helper `H` reached from workflow `W`]` for a transitive finding — plus an always-echoed `suppressed:` audit footer (AC5). `--list-suppressions` prints `file:line RULEID "reason"` per active suppression and exits `0` (AC6). Exit codes: `0` clean, `1` on any hard-blocker (or, with `--deny-warnings`, any warning); findings/JSON are always on stdout before the non-zero exit. New `CliError::DetCheckFindings { errors, warnings }` (exit code `1`, the default arm). Formatting/gating live in pure, unit-testable helpers (`det_check_report_for_paths`, `format_det_findings_text`, `format_det_suppressions`, `format_det_suppressions_list`, `det_check_json`, `det_check_gate`, `run_det_check`).

**AC4 boundary (mirrors #386):** `#[activity]` bodies, method/path-qualified calls, two-plus hops, third-party crates, trait-object dispatch, function pointers, and closures-captured-by-reference are all out of scope.

**Post-review hardening (four-agent review):** (1) **AC8 — bare `harvest det-check` at the repo root now exits `0`.** `collect_rs_sources` / `check_paths` skip any directory named `compile_fail` (alongside `target` and hidden dirs), so the deliberately-broken trybuild fixtures under `autumn-harvest/tests/compile_fail/` — true positives that exist to be rejected by the compile-time guardrail and carry committed `.stderr` snapshots — are no longer lint-flagged by the text pre-check; a bare `det-check` (default `.`) reports zero findings. (2) **Zero-FP — closures and fn-pointer params never resolve to a same-named free helper** (#386 explicitly excludes function pointers and closures). `collect_direct_free_fn_calls` now shadow-suppresses any call whose name is bound by the caller: parameter names (`FnDef.params`, over-collected from the param list via `extract_fn_params`) plus body `let`/closure bindings (`collect_body_let_idents`, reusing `det010_parse_let`). Safe-direction: a name that is both shadowed and legitimately a free-fn call is conservatively skipped (an accepted false-negative, never a false-positive). (3) **Multi-file / symlink / non-UTF-8 — one shared cross-path index.** New engine entry point `check_paths(&[&Path])` collects the full `.rs` source set across **all** path arguments into a **single** first-party index and scans once, so a cross-file transitive violation is caught even when the two files are passed as **separate** arguments (the `det-check $(git diff --name-only '*.rs')` changed-files CI pattern that per-file scanning silently missed — a false-negative on a determinism gate). It de-duplicates overlapping arguments (a dir plus a file inside it, or a repeated path) by canonicalized path so nothing double-counts; skips symlinked files and directories via `entry.file_type()?.is_symlink()` (a self-referential dir symlink can no longer explode the scan, and a `../..` symlink can no longer pull out-of-tree files in); and skips a single unreadable / non-UTF-8 `.rs` file mid-walk with a warning naming the file rather than `?`-aborting the whole scan. A missing top-level path argument still surfaces as an error. `check_dir`/`check_file` are unchanged. (4) **`--list-suppressions --format json` now emits JSON** (via the new `det_suppressions_json` helper) instead of silently falling back to the text listing; default stays text. **Post-review hardening (Codex P1 — module-scoped workflows).** The initial `extract_all_functions` rewrite tracked a **flat** brace-depth counter and skipped every line at depth `> 0`, which conflated a `mod NAME { … }` opener with an `impl`/`fn`/`struct` block — so a `#[workflow]` (or its first-party helper) declared inside a Rust module was **never scanned**, a broad false-negative: `harvest det-check .` could pass despite hard-blocker code in module-scoped workflows. **This was a regression introduced by #778's rewrite** — the superseded `extract_workflow_bodies` on trunk scanned for `#[workflow]` at any brace depth and therefore did scan module-nested workflow bodies (it simply lacked transitive helper resolution). The fix makes extraction **module-aware**: a `Vec<ScopeKind>` scope stack classifies each opening brace as transparent `Module` (`mod NAME { … }`, keep item-scanning inside, at any nesting depth) or `Opaque` (`impl`/`trait`/`struct`/bare block, skip contents), so module-scoped `#[workflow]` entry points and their module-scope helpers are scanned for direct and one-hop transitive violations while **methods inside `impl`/`trait` blocks remain excluded** (the #386 boundary — never indexed as free helpers, a `self.method()`/`Type::method()` callee is never resolved). `#[activity]` bodies remain unscanned at any nesting; a `fn` body's internals are still consumed wholesale by `extract_fn_body` (local fns inside a body are not indexed as top-level helpers). New pure helpers `is_mod_block_decl` (inline `mod NAME { … }` vs. external `mod NAME;`), `strip_leading_visibility`, and `apply_line_braces`/`apply_line_braces_stripped` (the scope-stack walker); the now-unused `code_brace_delta` was removed. Tests, TDD red→green (red confirmed against the pre-fix scanner): `module_scoped_workflow_direct_violation_is_flagged`, `module_scoped_workflow_transitive_helper_violation_is_flagged` (asserts `via_helper`), `nested_module_workflow_direct_violation_is_flagged`, `module_scoped_det010_hashmap_iteration_is_flagged`, and the two negative guards `module_scoped_activity_violation_is_not_flagged` / `impl_method_callee_is_not_resolved_as_helper` (in `det_check_tests.rs`); `is_mod_block_decl_matches_inline_modules_only`, `strip_leading_visibility_handles_pub_forms`, `apply_line_braces_classifies_module_vs_opaque` (unit tests in `det_check.rs`); and `module_scoped_workflow_direct_violation_trips_the_gate` (CLI behavioral test in `det_check_cli.rs`).

**Post-review hardening (Codex P1/P2 — scope-aware same-name resolution + turbofish calls).** Two false-negatives the module-aware rewrite left, both fixed TDD red→green. **(P1) Scope-aware same-name helper resolution.** The prior code marked any identifier defined by more than one plain free helper as globally ambiguous (`None`) and never resolved *any* workflow call to it — even when the calling workflow's own in-scope sibling was the obvious, Rust-correct target (e.g. `mod a { #[workflow] async fn wf() { stamp(); } fn stamp() { chrono::Utc::now() } }` alongside an unrelated `mod b { fn stamp() -> String }` reported no findings, skipping the reachable hard-blocker in `a::stamp`). Resolution is now Rust-accurate nearest-scope: a candidate in the caller's **own module** (same file + `module_path`) wins, else the sole candidate in the caller's **file**, else a **globally unique** candidate, else (multiple candidates, none in the caller's module/file scope) the call is conservatively skipped — the only remaining safe false-negative. This is a strict accuracy improvement with no added false-positive risk (preferring the same-module/same-file definition is exactly what the compiler resolves a bare call to). Shadow-suppression still runs first, so a locally-bound name is never resolved. Implementation: `FnDef` gains a `module_path` (the `mod`-nesting path, tracked in `extract_all_functions` via a `mod_stack` maintained in lockstep with the `Module` scope entries — new `extract_mod_name` + `apply_line_braces_scoped`); the helper index changed from `HashMap<&str, Option<usize>>` to `HashMap<&str, Vec<usize>>`; new pure `resolve_helper(candidates, fns, caller)`. **(P2) Turbofish call form.** A generic first-party helper called with a turbofish (`bad::<u64>()`, `bad::<Vec<u8>>()`) had the byte `:` (not `(`) after the ident, so the call-paren matcher never scanned the helper body and a reachable violation was missed. `collect_direct_free_fn_calls` now skips an optional balanced `::<…>` segment (new `skip_balanced_angles`) before requiring `(`. The `.`/`:` before-guard is unchanged, so method (`x.method::<T>()`) and associated (`Type::assoc::<T>()`) turbofish calls are still never resolved. **Both fixes preserve every existing guarantee** — `#[activity]` bodies unscanned, impl/trait methods never indexed or resolved (#386), closure/fn-pointer shadow-suppression, and zero false positives on the real tree. Tests: `same_module_helper_resolves_over_unrelated_same_name`, `same_file_different_module_helper_disambiguates`, `genuinely_ambiguous_same_name_helper_is_skipped`, `same_name_impl_method_is_not_resolved_via_method_call`, `turbofish_helper_call_is_resolved`, `nested_generic_turbofish_helper_call_is_resolved`, `method_and_assoc_turbofish_are_not_resolved` (in `det_check_tests.rs`); `extract_mod_name_reads_the_module_identifier`, `skip_balanced_angles_matches_nested_generics` (unit tests in `det_check.rs`).

**Post-review hardening (Codex P2 — source-order shadow tracking).** The zero-FP shadow-suppression above used a **whole-body** shadow set: any locally-bound name (params + every `let` binding anywhere in the body) suppressed a call to that name, regardless of where the binding sat relative to the call. That over-suppressed a genuinely in-scope call: a free helper called **before** a later same-name `let` binding is resolved by Rust to the free helper (the binding is not yet in scope), but the whole-body set wrongly skipped it — a false-negative in AC4 transitive coverage (e.g. a free `fn bad()` reading `chrono::Utc::now()`, reached by a `bad()` call preceding a later `let bad = |x| …`, went unreported). Suppression is now **source-order aware** (`collect_body_let_idents` → `collect_body_let_binding_lines`, name → earliest binding line; `collect_direct_free_fn_calls` takes `params` + `let_binding_lines` and compares each call's source line): a `let` shadow suppresses a call only on a strictly-later source line (so a pre-shadow call — and a call on the binding's own line, `let bad = bad();` — resolves to the free helper, matching Rust); params still bind for the whole body. **No new false positive** — this only ever suppresses *less* than the whole-body set, so every previously-suppressed post-shadow call stays suppressed and the original closure / fn-pointer-param FP-avoidance (`local_closure_call_is_not_resolved_to_free_helper`, `fn_pointer_param_call_is_not_resolved_to_free_helper`) is preserved. A `let` shadow bound in an inner block already closed before an outer call still suppresses it (source-order, not full brace-scope tracking) — a documented safe-direction residual false-negative, never a false-positive. Tests, TDD red→green (red confirmed against the pre-fix whole-body set): `pre_shadow_call_resolves_to_free_helper_not_the_later_binding` and the residual pin `block_confined_shadow_before_call_is_a_documented_false_negative` (in `det_check_tests.rs`).

**Post-review hardening (Codex r4 — false-positive fix + raw identifiers).** Two more findings, both fixed TDD red→green. **(C) Removed the Rust-inaccurate same-file-different-module resolution (false positive).** `resolve_helper`'s prior order preferred the sole same-**file** helper (any module) before falling back to global uniqueness, but a bare call in a child module does **not** resolve to a same-file helper in a *different* module (a parent/sibling module of the file) unless brought in by a `use` — which this text-level analysis cannot see. So a module-scoped workflow doing `use crate::pure::helper; helper();` (real target: a clean `helper` imported from another file) had its call wrongly resolved to an unrelated file-root `fn helper()` and got that helper's `chrono::Utc::now()` reported as a hard blocker — a false positive that could **fail CI on innocent code**. Resolution is now: a **globally unique** helper resolves directly, else a helper in the caller's **own module** (same file + `module_path`), else — multiple candidates, none in the caller's own module — conservatively skipped (ambiguous). Removing the same-file preference is strictly *more* Rust-accurate and only ever resolves **fewer** calls (removes an FP; cannot add one); shadow-suppression and source-order tracking still run first, and the same-module nearest-scope resolution (the #386 module-nested P1 fix) is untouched. **(D) Raw-identifier function names are now parsed.** `fn_decl_name` accepts an optional `r#` prefix (`async fn r#gen(…)` — `gen` is a reserved keyword in edition 2024, so `r#gen` is a valid, increasingly-real workflow name), retaining the `r#` on the extracted name; previously the parser stopped at `r`, failed the tail sanity check, and the `r#`-named workflow's body was **never scanned** (a direct `chrono::Utc::now()` in it passed with zero findings — a false negative). Transitive `r#name()` *call* resolution is not added (a safe false-negative — the required coverage is that an `r#`-named workflow's own body is scanned). Tests, TDD red→green: `same_file_different_module_helper_is_not_resolved` (converts the now-incorrect `same_file_different_module_helper_disambiguates`, which asserted the buggy FP behavior — the real target is a `use`-imported helper, so the file-root helper's violation is not reachable and must not be flagged), `raw_ident_workflow_body_is_scanned` (in `det_check_tests.rs`), and raw-ident assertions added to the `fn_decl_name_handles_visibility_and_async` unit test (in `det_check.rs`). The FP fix improves accuracy and adds no new false positive; `same_module_helper_resolves_over_unrelated_same_name` (the #386 module-nested resolution) and the source-order shadow tests are unchanged and still pass.
