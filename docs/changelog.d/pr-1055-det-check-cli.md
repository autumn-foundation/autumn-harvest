**`harvest det-check` CLI — the runnable front door for `det_check`, plus one first-party hop of transitive reachability (issue #778).** Turns the already-shipped `det_check` engine (DET001–DET011, `harvest-suppress`, `DetCheckReport`, `has_hard_blockers`) — which had **no runnable front door** — into a governance gate authors actually invoke, and closes the exact coverage gap #386 punted: a non-deterministic call (`chrono::Utc::now()`, `rand::random()`, …) factored out of a `#[workflow]` body into a **first-party helper function the body calls directly** used to sail past `cargo build`, the macro lint, and the body scanner, only to DLQ post-deploy. **Read-only source analysis: no `WorkflowEvent` variant, no event-schema change, no migration, no change to the `::autumn_harvest::` macro-path contract, no runtime code touched.** *(PR #1055.)*

**Engine (`autumn-harvest/src/det_check.rs`):** (a) **serde (AC2)** — `DetSeverity` (with `#[serde(rename_all = "lowercase")]` → `"error"`/`"warning"`), `DetLocation`, `DetFinding`, `DetSuppression`, and `DetCheckReport` now derive `serde::Serialize` for `--format json`. (b) **`DetLocation.col` (AC1)** — a new `pub col: u32` (always `> 0`), computed as the 1-based character column of the matched substring in the raw source line for the substring-table rules (DET001–DET009, DET011); the bespoke DET010 pass and any offset-less site report `1`. (c) **`DetFinding.via_helper: Option<String>` (AC4)** — `#[serde(default, skip_serializing_if)]`; `None` for a direct-in-body finding (`workflow_name = Some(wf)`, unchanged), `Some(helper)` for a transitive finding (`workflow_name = Some(entry_point)`, `location` = the offending line inside the helper). (d) **Transitive reachability** — the old `#[workflow]`-only `extract_workflow_bodies` is generalized to `extract_all_functions`, which walks each file tracking brace depth and captures every **top-level** (file-depth-0) `fn` definition with `is_workflow`/`is_activity` flags and an owned body (so a cross-file index can outlive per-file line buffers); methods inside `impl`/`trait` blocks (depth > 0) are never captured. `check_source` resolves one-hop calls within one file; `check_dir` first builds a first-party function index across every `*.rs` in the tree, then follows one hop of **direct free-function calls** (`helper(` — never `x.helper(` method calls, never `m::helper(` path-qualified calls, never identifier-continuation) from each `#[workflow]` body into plain (non-workflow, non-activity) helpers, scans those helper bodies with the *same* per-body analysis (all rules, suppressions included), and attributes findings to the entry point via `via_helper`. **One hop only** (workflow → A → B is not followed into B); **`#[activity]` callees are skipped** (an activity legitimately reading the clock reached from a workflow is not flagged); a helper **name defined by more than one plain helper is ambiguous and never resolved**, so an ambiguous resolution can never introduce a false positive. Findings are deduped by `(rule_id, entry-workflow, file, line)`. `check_dir` now also **skips `target` and hidden directories** so a scan of a repo root stays fast and never lints generated code.

**CLI (`autumn-harvest-cli`):** new `harvest det-check [PATHS...]` subcommand (default `.`). Local `--format text|json` flag (distinct from the global `--output`), `--deny-warnings`, and `--list-suppressions`. Handled entirely in-process before the HTTP execute path (mirrors the Tui early-return; `api_request()` for it is `unreachable!`). Text mode prints `file:line:col DETxxx  (safe alternative: …)` per finding — with `[in helper `H` reached from workflow `W`]` for a transitive finding — plus an always-echoed `suppressed:` audit footer (AC5). `--list-suppressions` prints `file:line RULEID "reason"` per active suppression and exits `0` (AC6). Exit codes: `0` clean, `1` on any hard-blocker (or, with `--deny-warnings`, any warning); findings/JSON are always on stdout before the non-zero exit. New `CliError::DetCheckFindings { errors, warnings }` (exit code `1`, the default arm). Formatting/gating live in pure, unit-testable helpers (`det_check_report_for_paths`, `format_det_findings_text`, `format_det_suppressions`, `format_det_suppressions_list`, `det_check_json`, `det_check_gate`, `run_det_check`).

**AC4 boundary (mirrors #386):** `#[activity]` bodies, method/path-qualified calls, two-plus hops, third-party crates, trait-object dispatch, function pointers, and closures-captured-by-reference are all out of scope.

**AC8 (tree is clean):** `harvest det-check autumn-harvest/src autumn-harvest/examples autumn-harvest-plugin/src autumn-harvest-cli/src` reports **zero** hard-blocker findings in ~0.9 s. One pre-existing offender surfaced and was resolved with the sanctioned escape hatch: `autumn-harvest/examples/deterministic_primitives.rs` reads `std::env::var("DEPLOY_REGION")` **inside a `ctx.side_effect(...)` closure** (a deterministic, recorded-once read the text scanner can't see through) — suppressed with `// harvest-suppress: DET004 "env read is wrapped in ctx.side_effect(); recorded once and replayed deterministically"`. A whole-workspace `harvest det-check .` scan (~1.4 s) surfaces only the deliberately-non-deterministic trybuild fixtures under `autumn-harvest/tests/compile_fail/` — **true positives** that exist precisely to be rejected by the compile-time guardrail, left unmodified (a comment line would shift their committed `.stderr` snapshots and break the macro tests).

**Post-review hardening (four-agent review):** (1) **AC8 — bare `harvest det-check` at the repo root now exits `0`.** `collect_rs_sources` / `check_paths` skip any directory named `compile_fail` (alongside `target` and hidden dirs), so the deliberately-broken trybuild fixtures under `autumn-harvest/tests/compile_fail/` — true positives that exist to be rejected by the compile-time guardrail and carry committed `.stderr` snapshots — are no longer lint-flagged by the text pre-check; a bare `det-check` (default `.`) reports zero findings. (2) **Zero-FP — closures and fn-pointer params never resolve to a same-named free helper** (#386 explicitly excludes function pointers and closures). `collect_direct_free_fn_calls` now shadow-suppresses any call whose name is bound by the caller: parameter names (`FnDef.params`, over-collected from the param list via `extract_fn_params`) plus body `let`/closure bindings (`collect_body_let_idents`, reusing `det010_parse_let`). Safe-direction: a name that is both shadowed and legitimately a free-fn call is conservatively skipped (an accepted false-negative, never a false-positive). (3) **Multi-file / symlink / non-UTF-8 — one shared cross-path index.** New engine entry point `check_paths(&[&Path])` collects the full `.rs` source set across **all** path arguments into a **single** first-party index and scans once, so a cross-file transitive violation is caught even when the two files are passed as **separate** arguments (the `det-check $(git diff --name-only '*.rs')` changed-files CI pattern that per-file scanning silently missed — a false-negative on a determinism gate). It de-duplicates overlapping arguments (a dir plus a file inside it, or a repeated path) by canonicalized path so nothing double-counts; skips symlinked files and directories via `entry.file_type()?.is_symlink()` (a self-referential dir symlink can no longer explode the scan, and a `../..` symlink can no longer pull out-of-tree files in); and skips a single unreadable / non-UTF-8 `.rs` file mid-walk with a warning naming the file rather than `?`-aborting the whole scan. A missing top-level path argument still surfaces as an error. `check_dir`/`check_file` are unchanged. The CLI's `det_check_report_for_paths` now calls `check_paths` once instead of merging per-path `check_file`/`check_dir` reports. (4) **`--list-suppressions --format json` now emits JSON** (via the new `det_suppressions_json` helper) instead of silently falling back to the text listing; default stays text. (5) **Docs:** the AC7 GitHub Actions job and pre-commit hook use the now-clean argless `harvest det-check` (the old `det-check src examples` recipe failed on this repo, which has no root `src/`), with a note that a larger downstream workspace can enumerate specific crate `src` directories; a new "Known limitations (conservative, safe-direction)" note documents the ambiguity guard, local shadowing, path-qualified/associated-call non-resolution, and turbofish/space-before-paren call-form gaps as deliberate false-negatives (never false-positives) with the compile-time #386 guardrail as the authoritative backstop; a "Flag scope" note records that `det-check` has its own local `--format` and ignores the global network/`--output` flags; and a DET010/DET011 reconciliation sentence clarifies that `det-check` surfaces the entire shared engine (including the pre-existing DET010 HashMap-iteration and DET011 select rules) — #778 adds no new HashMap/data-structure linting, but does not hide the engine's existing DET010 output.

**Post-review hardening (Codex P1 — module-scoped workflows).** The initial `extract_all_functions` rewrite tracked a **flat** brace-depth counter and skipped every line at depth `> 0`, which conflated a `mod NAME { … }` opener with an `impl`/`fn`/`struct` block — so a `#[workflow]` (or its first-party helper) declared inside a Rust module was **never scanned**, a broad false-negative: `harvest det-check .` could pass despite hard-blocker code in module-scoped workflows. **This was a regression introduced by #778's rewrite** — the superseded `extract_workflow_bodies` on trunk scanned for `#[workflow]` at any brace depth and therefore did scan module-nested workflow bodies (it simply lacked transitive helper resolution). The fix makes extraction **module-aware**: a `Vec<ScopeKind>` scope stack classifies each opening brace as transparent `Module` (`mod NAME { … }`, keep item-scanning inside, at any nesting depth) or `Opaque` (`impl`/`trait`/`struct`/bare block, skip contents), so module-scoped `#[workflow]` entry points and their module-scope helpers are scanned for direct and one-hop transitive violations while **methods inside `impl`/`trait` blocks remain excluded** (the #386 boundary — never indexed as free helpers, a `self.method()`/`Type::method()` callee is never resolved). `#[activity]` bodies remain unscanned at any nesting; a `fn` body's internals are still consumed wholesale by `extract_fn_body` (local fns inside a body are not indexed as top-level helpers). New pure helpers `is_mod_block_decl` (inline `mod NAME { … }` vs. external `mod NAME;`), `strip_leading_visibility`, and `apply_line_braces`/`apply_line_braces_stripped` (the scope-stack walker); the now-unused `code_brace_delta` was removed. Tests, TDD red→green (red confirmed against the pre-fix scanner): `module_scoped_workflow_direct_violation_is_flagged`, `module_scoped_workflow_transitive_helper_violation_is_flagged` (asserts `via_helper`), `nested_module_workflow_direct_violation_is_flagged`, `module_scoped_det010_hashmap_iteration_is_flagged`, and the two negative guards `module_scoped_activity_violation_is_not_flagged` / `impl_method_callee_is_not_resolved_as_helper` (in `det_check_tests.rs`); `is_mod_block_decl_matches_inline_modules_only`, `strip_leading_visibility_handles_pub_forms`, `apply_line_braces_classifies_module_vs_opaque` (unit tests in `det_check.rs`); and `module_scoped_workflow_direct_violation_trips_the_gate` (CLI behavioral test in `det_check_cli.rs`).
