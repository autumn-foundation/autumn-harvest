## Tooling — Heal two RED `trunk-dev` failures after a merge burst (PR #1094)

A merge burst left `trunk-dev` red on two independent gates; this PR heals both (precedent: PR #1078 folded two lint heals into one PR).

**1. Missing route classification (`contract_regression`).** PR #1092 added the read-only route `GET /workflows/registered/{name}/interface` to the plugin's `management_api_routes()` but never classified it in `autumn_harvest::audit`, so the plugin's `contract_regression::every_management_route_is_classified` test — which enforces that every `management_api_routes()` entry has a `CLASSIFIED_ROUTES` entry (issue #776 AC4 read-only enforcement source of truth) — failed on every trunk-based branch. Classified the route `ReadOnly`, exactly mirroring its existing sibling `GET /workflows/registered/{name}/schema`, across all four audit lists in `autumn-harvest/src/audit.rs`: `CLASSIFIED_ROUTES` (`RouteClass::ReadOnly`), `EXCLUDED_ROUTES` (read, no audit trail), `ALL_MUTATION_ROUTES` (op `None`), and the `newly_classified_reads_are_read_only` pin test. `CLASSIFIED_ROUTES.len()` and `ALL_MUTATION_ROUTES.len()` stay balanced (one entry added to each), so `classified_routes_count_matches_route_manifest` still holds.

**2. `clippy::redundant_closure_for_method_calls` (`-D warnings`).** PR #1093 merged while draft (CI skipped), introducing a redundant-closure lint failure in `autumn-harvest-plugin/tests/start_throttle_integration.rs` — `body["results"].as_array().map_or(0, |a| a.len())`. Replaced the closure with the method itself (`Vec::len`), which is behavior-identical and accepted by both clippy 1.94.1 (stable) and 1.97.0. The sibling `.map_or(0, |e| e[...].as_i64().unwrap_or(0))` on line 1896 is a non-trivial closure and is correctly not flagged.

No production code or runtime behavior change beyond making the already-shipped `/interface` route reachable by a read-only principal and excluded from audit (consistent with the `/schema` sibling). No new `WorkflowEvent` variant, no migration.
