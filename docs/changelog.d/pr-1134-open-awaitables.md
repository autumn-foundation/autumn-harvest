## Phase 3.53 — Open-awaitables diagnostic: why is this execution parked? (issue #615)

**Implemented.** New read-only management route `GET /api/harvest/workflows/{id}/awaitables` (admin-gated, the eligibility endpoints' posture) answering "what is this run waiting on right now?" in one call — including the waits **no side table can see**: an awaited-but-unsent signal and an unresolved `ctx.await_condition` park, which exist only as parked commands inside the replayed coroutine. **Derivation:** the endpoint loads the recorded history once (`store::load_history_with_timestamps`), replays it read-only to the current suspension point via the #612 `drive_query_replay_async` machinery — with worker-fidelity context threading (`execution_timeout`/`deadline_at`/`parent_execution_id`/`workflow_name`/`workflow_id`/`context_headers` #481, declarative query/update handler registration, `registry.shared_state()`, `registry.history_policy()`) and real payload inflate/decode (offload #524 + runtime codecs #608, decoded plaintext feeding only the drive — the response is payload-free by construction) — then projects the drained pending-command buffer through the new pure, no-DB core module **`autumn-harvest/src/awaitables.rs`** (`project_awaitables`, `Awaitable{kind,name,id,since,deadline,local,external}`, `AwaitableKind`, `WaitSetInput`, `AwaitablesProjection`; re-used verbatim by the Vantage UI so the two can never disagree). **All six issue categories covered** — pending activities (regular/local/external-handoff), unfired durable timers, awaited-but-unfulfilled signals (by name), pending child workflows (name + child exec id), unresolved `await_condition` parks (inferred from a command-less non-transitioning suspension), and pending updates (`UpdateAdmitted` with no recorded terminal, minus any update resolved in the drained cycle) — plus two bonus kinds: parked mutex acquires (#691) and external-workflow await/signal/cancel operations (#757/#244/#492). Signal-or-deadline (#476) and child-or-deadline (#779) reserved race timers (`__signal_timeout:{seq}:{name}` / `__child_timeout:{seq}:{name}`) are **folded into their signal/child awaitable's `deadline`** rather than surfacing as internal timer rows (an orphan race arm degrades to a plain timer so nothing is silently dropped). Each awaitable carries `kind`, name/identifier, a `since` timestamp derived from its own recorded scheduling/arming event (falling back to the last-event suspension point for command-only waits), and a `deadline` where one applies — timer fire time, race deadline, external schedule-to-close (cleared on `ActivityExternalDeadlineExtended`, whose event carries no new value), and open activity awaitables enriched with the earliest of the task row's cross-retry `schedule_to_close_at` (#378) and the current attempt's `started_at + start_to_close`. **Degradation contract (a triage endpoint degrades, it never errors):** an unregistered handler (`handler_not_registered`), classic DAG (`classic_dag`), payload inflate/decode failure (`payload_decode_required`), replay timeout (`replay_timed_out`), contained handler panic (`replay_panicked`), a suspended drive carrying a deferred non-determinism error (`replay_diverged`), or a replay reaching `Poll::Ready` on a non-terminal row (`replay_reached_terminal`) falls back to a best-effort `wait_set = "history_only"` event-log scan with `wait_set_reason` naming why — activities/timers/children/updates/external awaits still report; awaited-unsent signals (except race-encoded ones) and condition parks are the documented blindness of that mode. Resolved races leave **no stale arms** in history-only mode: a signal-win/child-win tears its reserved deadline timer down via an event-less `CancelRaceLosers` row delete, so the history index closes the oldest open matching arm at the resolving `SignalReceived`/child terminal (a timer-win's arm was already closed by its recorded `TimerFired`, making a late signal a no-op). Terminal executions return `200` with an EMPTY list, `wait_set = "terminal"`, and the state echoed; `SUSPENDED` is not a persisted state (the state CHECK constraint forbids it), so RUNNING/PAUSED coverage is the whole non-terminal surface. **Bounds:** first `category_cap` (50) entries per kind in recorded/command order, overflow surfaced via `truncated`/`truncated_kinds` (exactly-cap is not truncation; truncation is per-category). **Vantage UI:** the workflow-detail blocked-on panel is re-sourced from the same `build_awaitables_report` (admin-gated via `has_harvest_admin_access`, non-terminal runs only, best-effort with a history-only banner naming the reason), now rendering children, awaited-unsent signals, and condition parks. **CLI:** `harvest workflow awaitables <execution_id>`. **No new `WorkflowEvent` variant, no migration, zero writes** — proven by an integration test snapshotting the execution row, event count, and the task/timer/signal side tables before/after; shard-local read via `db_conn_for_execution` (O(1) from the exec id's embedded shard), no cross-shard fan-out; the pool connection is dropped before any payload fetch or user-code drive (the #612 pool-slot discipline, widened to offload I/O). Route registered across all five parallel registries (axum router, `management_api_routes()`, `management_api_response_fields()`, `docs/api-contract.json`, and `audit.rs` `CLASSIFIED_ROUTES` ReadOnly / `EXCLUDED_ROUTES` / `ALL_MUTATION_ROUTES` None) with pinned classification tests in both `audit.rs` and plugin `contract_regression.rs`, plus `security.rs::eris_unauthenticated_awaitables_is_blocked` (401). **Known approximations** (documented in the module docs, from the replay review): the #612 drive stops at the first command-emitting poll (a hand-rolled future that yields before awaiting could be absent), the Condition kind is an inference from a command-less, non-transitioning, **non-update-resolving** suspension (a drained `RecordUpdateResult` — an admitted update whose result is committing this cycle, its `UpdateCompleted` not yet persisted — is excluded from the inference so an in-flight update-result commit is not misread as a phantom `await_condition` park; pure-bookkeeping commands like `set_current_details` still precede a genuine cold park and are left alone; the deferred-ND check guards the divergence case), and an `ArmTimer { for_await: true }` deadline is anchored at its recorded ARM time while the true #768 deadline anchors at `await_fire`. **Success metric:** 10k-event projection measured at ~27 ms in debug builds (p95 < 1 s budget met with orders-of-magnitude headroom); 100% of the six categories covered by per-category tests. **Tests, TDD red→green→refactor + four-angle review (security / performance / replay-determinism / test-quality, all P1/P2 findings fixed):** 31 pure no-DB core tests in `tests/integration/awaitables_tests.rs` (falsifiable delta `unsent_signal_awaitable_is_named`, per-category coverage, race folds both modes, resolved-race regressions, synthetic command arms, truncation boundaries, `since`-provenance fixtures with trailing benign markers, 10k-event scale) + 3 inline module tests; 10 plugin DB/HTTP/UI tests in `autumn-harvest-plugin/tests/awaitables_integration.rs` (dual-mode `HARVEST_TEST_DATABASE_URL`/testcontainers, executed green against a real local Postgres 16; registered in `.github/ci/integration-suites.txt` for the Docker-backed Linux CI run) covering the falsifiable delta end-to-end, task-row deadline enrichment incl. earliest-of, child reporting, terminal echo, degrade reasons (`handler_not_registered`, `replay_reached_terminal`, `replay_panicked`, `replay_diverged`), zero-writes, stable error statuses (404/400), and the UI panel (signal + child rendering, terminal negative control); CLI mapping/coverage tests.
