- **Phase 3.x** (implemented): In-flight replay-drift gate — sample what is running now, replay it against the candidate build, block promotion on divergence (issue #798). A determinism regression in a `#[workflow]` body does not fail at compile time and does not fail on a fresh run: it fails when an **already-running** execution is resumed by the new code, minutes or hours after the deploy, by which time the run is nd-blocked (#603) or dead-lettered. The pre-existing `ReplayVerifier` (#251) replays a *curated fixture directory of completed histories* **strictly** and cannot answer the deploy question ("will the executions running right now survive this build?"); the replay canary (#512) can, but only *server-side, after* the build is already reachable. This slice closes that window with a CI-side loop: one read-only export command plus a ~15-line gate binary in the embedder's own crate.

  **Core — `replay_sample.rs`** (new, pure, no DB, unconditional): the single source of truth for the bundle wire shape, shared by the API (producer), the CLI (writer), and the testing harness (reader). `IN_FLIGHT_STATES` (`RUNNING`/`PAUSED`), `DEFAULT_PER_WORKFLOW_SAMPLE` (50), `MAX_PER_WORKFLOW_SAMPLE` (500), `MAX_SAMPLE_TOTAL` (2000); `SampleOrder` (`Oldest`/`Newest`), `SampleStatus` (`Complete`/`Partial`/`Unavailable`, `from_counts`); `SampleWorkflowCoverage { workflow_name, sampled, in_flight_total }` with `truncated()`; `SampleManifest` (with the reserved `FILE_NAME = "harvest-sample-manifest.json"`, `is_complete()`, `is_truncated()`); `normalize_sample_states`, `clamp_per_workflow`, `merge_coverage`, `fixture_file_name`. **`SUSPENDED` is accepted as a documented alias for `RUNNING`** — the AC's literal default state set names it, but `SUSPENDED` is not a persisted state (it is absent from `KNOWN_WORKFLOW_STATES` and forbidden by the CHECK constraint; a parked run's row is `RUNNING`), so the alias makes the AC's default resolve to the correct non-terminal set. A **terminal** state in `states` is rejected (`Err`), never silently dropped — the gate replays in-flight histories, so a request for `COMPLETED` is a caller error, not an empty result. `fixture_file_name` sanitizes the workflow name to `[A-Za-z0-9_-]`, caps both components at 64 chars, and appends the execution UUID so a hostile or merely awkward name can never escape the bundle directory.

  **Core — `ReplayDriftReport` + `replay_bundle` (`testing.rs`, feature `testing`)**: `WorkflowReplayer::replay_bundle(dir)` and `ReplayVerifier::replay_bundle(dir)` return `ReplayDriftReport { total, succeeded, diverged: Vec<ReplayDrift>, blocked: Vec<ReplayBlocked>, skipped, coverage: Option<SampleManifest>, … }`, where each `ReplayDrift` carries `execution_id`, `workflow_name`, `kind: NonDeterminismKind`, `first_divergence`, and `fixture_path`. **The load-bearing design decision is the replay MODE.** Wiring `replay_bundle` to the existing `verify_dir` would have made the gate **100% false-red on every in-flight fixture**: `verify_dir` → `replay_from_snapshot` → `outcome_to_report(.., canary_mode: false)`, whose `WorkflowOutcome::Suspended` arm returns `NonDeterminismDetected` — but a healthy non-terminal execution *always* suspends at its recorded frontier; that is its correct outcome. `replay_bundle` therefore uses the new private `FixtureReplayMode::InFlight` → `replay_canary_snapshot`, while `verify_dir` keeps `FixtureReplayMode::Strict`; both share one `replay_dir` engine so there is one replay path with two documented modes rather than a fork. Genuine divergences still fail in canary mode (they surface as `WorkflowOutcome::Failed { non_deterministic_details: Some(_) }`) and leftover unconsumed history is still caught. **Verified by falsification**: swapping the mode to `Strict` made 5 tests fail including the money test; restored and re-verified green.

  **The false-GREEN failure mode is closed too.** `verify_dir` over an empty or mistyped directory returns `fixtures_total: 0` → exit 0; a gate that passes having verified nothing is worse than no gate. `is_clean()` is *defined* as `exit_code() == 0` so the two helpers can never disagree, and the exit ladder is: `0` clean · `1` diverged · `2` blocked (a fixture the harness could not evaluate — dominates `1`, mirroring `CiReport`) · `3` **empty bundle** (opt out with `allow_empty_bundle(true)` for a legitimately idle fleet) · `4` `require_complete_coverage(true)` and the manifest reports partial shard coverage. `collect_json_files` excludes the reserved manifest filename, so a well-formed bundle never produces a spurious harness error — and the pre-existing `verify_dir` is protected from breaking on a #798 bundle.

  **Plugin — `GET /admin/history/export-sample`** (new, admin-gated, read-only): stratified in-flight sample export. **One statement, two window functions** (`HISTORY_SAMPLE_CANDIDATES_{OLDEST,NEWEST}_SQL`): `ROW_NUMBER() OVER (PARTITION BY workflow_name ORDER BY started_at, id)` performs the stratification — without it a plain `LIMIT` returns the noisiest workflow type's rows and nothing else, the exact failure this route exists to prevent — and `COUNT(*) OVER (PARTITION BY workflow_name)` reports the population the sample was drawn from. Computing both in the *same* statement is what makes `sampled <= in_flight_total` true by construction; a second query could observe a different snapshot and report a sample larger than its own population. Two SQL constants rather than an interpolated `ORDER BY` direction (which would be an injection seam), selected by a `const fn`. Deliberately **no `harvest_events` join**: the batch export needs one for `last_history_event_at`, but that column is only ever a sort key there and is never carried into the export document, so the sample orders by the indexed `started_at` and stays cheap on a large in-flight fleet. **The per-type cap is global, not per shard**: each shard returns its own top-N (a superset of the global top-N, since an execution in the global top-N is necessarily in its own shard's top-N), then `stratify_sample_rows` re-sorts the union by the same key and re-truncates — so `--per-workflow 50` means 50 fleet-wide. A new `HistorySampleCandidate` converts into the existing `HistoryExportCandidate`, so the **entire** batch-export pipeline is reused unchanged (payload policy, #608 read-path decoding, `max_bytes`, per-entry failure reporting, shard coverage) — which is also how AC3 is satisfied for free. An unreachable shard degrades the manifest to `partial` and names the shard rather than failing the request. Registered in all four parallel registries (`harvest_api_router`, `management_api_routes()`, response-fields, `docs/api-contract.json`) and in `autumn_harvest::audit` (`CLASSIFIED_ROUTES` `ReadOnly` / `ALL_MUTATION_ROUTES` `None` / `EXCLUDED_ROUTES`), with a pinned `history_export_sample_route_is_classified` guard in `contract_regression.rs` (the audit-side mutual cross-check stays green if a route is dropped from BOTH lists). Read-only classification matters twice here: the route feeds a CI gate, and a misclassification as `Mutating` would make it unreachable to the read-only operator role (#776) a CI token is most likely to hold. It is admin-gated; the older `/admin/history/exports` sibling predates that posture and is left as-is (tightening an existing route's auth is out of scope).

  **AC2 — no silent truncation.** A workflow type whose entire sample failed the per-execution size ceiling still appears in the manifest with `sampled: 0` and its real `in_flight_total`, so an operator can never mistake "nothing was exported for this type" for "this type has nothing in flight". `sampled` is counted from the documents **actually exported**, not from the rows selected, so a size-limit failure is never counted as a sample.

  **CLI — `harvest history export-sample --output-dir <DIR>`** with `--per-workflow`, `--states` (repeatable **and** comma-separated, so a recipe copied from either idiom samples the same population), `--workflow-name`, `--order`, `--shard-id`, `--payload-policy`, `--max-bytes`. Writes a replay **bundle** (one `.json` fixture per sampled execution plus `harvest-sample-manifest.json`) rather than a single blob, so the directory feeds straight into `replay_bundle`; `-o json` still prints the raw response for scripting. The writer is split into two pure, unit-tested functions — `history_sample_bundle_files` (which files, named how; a sanitization collision is disambiguated, never overwritten, since overwriting would silently shrink the bundle below what the manifest claims) and `render_history_sample_summary` (the coverage table, which prints a `WARNING … LOWER BOUND` block on partial shard coverage and a `NOTE: the sample is truncated` line whenever `sampled < in_flight_total`). A non-sample response body fails loudly rather than writing an empty bundle a gate would then evaluate for the wrong reason.

  **AC7 — zero new `WorkflowEvent` variants, no migration.** The export is `SELECT`-only (no state transition, no event appended, no task claimed) and the replay is pure. Nothing in this slice touches `harvest_events`, the adjacently-tagged event JSON contract, or the shard-routing model.

  **Post-review hardening (four reviewers: replay-determinism, sharding/SQL, CI-gate honesty, tests/AC-evidence).** Every finding is a variant of one failure: *the gate says something confidently false*. (1) **A redacted bundle is refused, not replayed.** The CLI's `--payload-policy` default is `redacted`, and redaction rewrites payload-bearing fields **in place** — but both replay paths run with `strict_replay = true`, so `match_activity_strict` compares the redacted stub against the input the code computes and **every** fixture passing a non-trivial activity input diverges. Replaying such a bundle does not produce a weaker gate, it produces a confidently wrong one that reports a determinism regression in code that is fine. The new `unreplayable_fixture_reason` refuses it as a *harness error* (exit 2) naming the fix, alongside a wrong-population check (a terminal fixture handed to the in-flight gate, or vice versa). The two fields it reads are export-document metadata, so they are parsed from the fixture JSON via a private `FixtureGuardFields` side struct rather than added to `HistorySnapshot` — which would have forced every hand-built fixture in the workspace to declare export metadata it has no notion of. Empirically confirmed RED: before the guard, a redacted bundle reported `0 clean, 1 diverged`. (2) **`require_complete_coverage` fails closed.** It previously passed when the manifest was **missing or unparseable** (`read_bundle_manifest` is fail-open by design). A caller who sets that flag has said they will not certify against a partial read of the fleet, and *no manifest proves nothing* — so absent evidence now exits 4 via the new `coverage_claim_unsatisfied()`, deliberately stricter than `has_incomplete_coverage()` (which correctly answers the different question "did the bundle *claim* partial coverage?"). (3) **Alphabetical starvation.** `MAX_SAMPLE_TOTAL` was applied as a running total over name-sorted rows, so a fleet with more types than budget gave the alphabetically-late ones **zero** coverage while the gate exited 0 — the same "noisy crowds out quiet" failure the per-type stratification exists to prevent, on a different axis. The global cap is now divided across the observed type count. Confirmed RED at 60 types: 40 covered, 20 silently blind. (4) **Two logical shards sharing one physical database double-counted.** The sample query had no `shard_id` predicate (every other cross-shard count in the repo carries one — `COUNT_WHERE_CLAUSE`, `schedule_run_state_summary`, `non_terminal_counts_by_workflow_name`), so the fan-out ran the same statement twice over the same rows: `in_flight_total` doubled — corrupting the exact denominator AC2 exists to state honestly — **and** every execution was sampled twice, halving real per-type coverage while `sampled` looked unchanged. Both silent. Confirmed RED end-to-end: 3 executions reported `in_flight_total: 6` with every fixture duplicated. (5) **The liveness canary (#796) leaked into bundles.** Its probe workflow is engine-internal and registered by no user gate binary, so a sampled probe lands in `blocked` — which dominates the exit ladder — pinning the gate at exit 2 forever on any deployment that enables the canary. Excluded with `starts_with`, not `LIKE` (the prefix is underscore-heavy and `_` is a `LIKE` wildcard), with a test pinning the literal to `canary::CANARY_WORKFLOW_NAME_PREFIX`. (6) **Re-exporting into a directory replaces the bundle.** Fixture names embed the execution id so they never overwrite — they *accumulate* — while the manifest has a fixed name and *is* overwritten, so the gate replayed executions from every past run while the coverage record described only the latest. Cleaning is scoped narrowly: only when the manifest marker is present, only top-level `*.json`, and using the *same* extension predicate the gate's own walk uses so a stale fixture cannot survive the clean and still be replayed. A JSON-bearing directory with no manifest is **refused**, so `--output-dir .` cannot eat a user's files. (7) `context_headers` are now carried through the sample export, so a workflow reading ambient headers replays against the same ones it saw live instead of false-diverging. (8) **The docs recipe did not work**: the Rust snippets did not compile (`workflows![]` takes bare fn names, and `allow_empty_bundle`/`require_complete_coverage` live on `ReplayVerifier`, not `WorkflowReplayer`), the CI job used a nonexistent `HARVEST_API_URL` (it is `HARVEST_URL`), the flag table advertised a phantom `omit` policy value, and the headline two-command loop omitted `--payload-policy full` — so following it verbatim produced a bundle the gate now refuses. All fixed, and the CLI now warns at **write** time when it produces a redacted bundle, so the problem surfaces when the bundle is created rather than as a wall of BLOCKED lines later.

  **Tests:** 14 core no-DB tests in `tests/integration/replay_drift_tests.rs` (the money test `in_flight_bundle_replays_clean_against_unchanged_code`, full-detail divergence reporting, all-diverged-not-just-the-first, the empty-bundle ladder and its opt-out, missing-directory and unparseable-fixture harness errors, unregistered-workflow blocking and its `allow_unregistered` downgrade, agreement with the strict verifier, manifest coverage surfacing, partial-coverage gating, JSON serialization, and `Display`); 16 pure unit tests in `replay_sample.rs`; 9 pure unit tests in the plugin (`stratify_sample_rows` per-type cap / cross-shard re-truncation / newest order, `shard_population`, the SQL shape asserting the stratification window and the absence of an events join, and the query-parser defaults/rejections/clamp); 14 DB/HTTP integration tests in `autumn-harvest-plugin/tests/replay_sample_export_integration.rs`; 8 pure CLI bundle-writer unit tests plus 5 request-mapping and 1 contract-coverage test. **The end-to-end money test** `exported_bundle_passes_the_gate_and_catches_a_reordering_regression` drives the whole loop through the real HTTP route: seed three in-flight executions → `GET /admin/history/export-sample` → write the bundle → `replay_bundle` returns clean against the code that produced the history (`total == 3`, `coverage.is_some()`), and non-zero with all three divergences reported against a build that swapped two activities. **Falsified**: pointing the drift half at the unchanged workflow makes it fail with `3 clean, 0 diverged`, confirming the assertion is load-bearing rather than vacuous. All DB/HTTP suites were executed green against a real local Postgres 16 (Docker unavailable in the implementing sandbox); one sorted row added to `.github/ci/integration-suites.txt` so CI runs them Docker-backed on Linux.

  **Success metric, measured.** `thousand_execution_cross_shard_sample_exports_and_replays_within_budget` (`#[ignore]`d — it seeds 1,000 executions; run it deliberately) substantiates the issue's own number end to end: 1,000 in-flight executions spread across **2 shards** and **20 workflow types** (so the sample is genuinely stratified rather than one type's rows), exported through the real HTTP route and replayed through `replay_bundle`. Measured **26.4 s** wall clock in a debug build, with the phase split printed for diagnosability: **export 0.89 s + bundle write 0.14 s + replay 25.5 s**. The DB-bound half — the part that actually scales with fleet size and shard count — is under a second; replay is pure local CPU and accounts for ~96% of the clock. The test asserts **both** halves of the metric against the same bundle, because it is only meaningful as a pair: unchanged code must replay clean, *and* a reordering regression must be reported on **all 1,000** sampled executions (zero false negatives — a gate that is fast because it verifies nothing satisfies neither half). The budget is **build-mode aware** (30 s release, 120 s debug): the metric describes the operator-facing gate, which ships release-built, so asserting 30 s against a debug build would assert something far stricter than the metric and flake on a loaded runner. Release replay throughput is separately pinned by the pre-existing `replay_verifier_bench` (issue #251) at 1,000 fixtures averaging **1k events each** in under 30 s, versus ~3 events per fixture here — so the debug figure is the conservative bound, not the representative one.
