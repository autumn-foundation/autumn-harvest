## Tooling — Sweep hand-rolled test INIT_SQL bundles onto full_migrations_sql() (PR #1045)

Followed up PR #1031 by converting 87 db-gated integration-test fixtures (51 in `autumn-harvest/tests/integration/`, 36 in `autumn-harvest-plugin/tests/`) from hand-maintained `concat!(include_str!(".../migrations/.../up.sql"), ...)` bundles onto the paved-path helper `autumn_harvest::full_migrations_sql()` (the `build.rs`-generated, drift-proof full-migration bundle). Each converted fixture now builds its schema via a module-level `fn init_sql() -> Vec<u8> { autumn_harvest::full_migrations_sql().as_bytes().to_vec() }` at `with_init_sql(...)` sites and `autumn_harvest::full_migrations_sql()` (a `&str`) directly at `batch_execute(...)` sites; the stale `const INIT_SQL` bundles — which had drifted 8–71 migrations behind the current 73, and had accumulated hand-patched inline `ALTER`/`ADD COLUMN` hotfixes for exactly this drift — are deleted (net −9918 lines). Non-migration setup is preserved verbatim (the separate app-DB `OUTBOX_INIT_SQL` migration, the `SCHED_COLS`/`CREATE_USER_RECORDS` post-bundle patches, the `__diesel_schema_migrations` seed + `CARGO_MANIFEST_DIR` path helper in `status_summary_integration.rs`, and `CREATE DATABASE`/`SET enable_seqscan`/`BEGIN`/`COMMIT` statements).

Three fixtures are deliberately left on partial hand-rolled bundles (documented in-file), because their test logic depends on a schema the full bundle would change: `integration_e2e.rs` (`INIT_SQL` excludes the workflow-start-uniqueness migration, and `LEGACY_INIT_SQL` reconstructs the historical one-step-at-a-time upgrade path); `autumn-harvest-plugin/tests/schedule_update_integration.rs` (omits `harvest_start_throttle` so the scheduler tick's `to_regclass` graceful-degradation path is exercised); and `autumn-harvest-plugin/tests/timeline_integration.rs` (its `timeline_classic_dag_run_returns_404` test inserts a row directly into `harvest_dag_runs`, which the full bundle drops via `20260514000000_drop_harvest_dag_runs` — surfaced by executing the suite, not by static analysis).

No production code, no `WorkflowEvent` variant, no migration, no CI-suite manifest change. The drift guards (`migration_hygiene::full_migrations_sql_bundle_is_complete`, `ci_run_coverage`) stay green. Verification: `cargo fmt --check` and `cargo clippy --all-features --tests -- -D warnings` clean on both crates; the core integration binary (all 51 converted modules) and 35 plugin integration targets executed against real Postgres 16 via testcontainers — every test green except a handful of pre-existing failures proven to fail identically against the original hand-rolled bundles (stale pre-#603 semantics in `metrics_integration`; a µs/ns timestamp self-comparison in `schedule_runs_tests`; admission-gate ordering in `start_throttle_integration`; a wrong-table `updated_at` SELECT and a 410-vs-408 replay classification in `query_integration`), all unrelated to the migration bundle and out of scope. Unblocks progressively wiring these suites into CI and shrinking the `ci_run_coverage` allowlist toward zero (PR #1031's recommended follow-up).
