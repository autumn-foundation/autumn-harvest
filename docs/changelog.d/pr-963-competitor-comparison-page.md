## Docs — Honest competitor comparison page (issue #963)

**Docs-only** (implemented): New `docs/comparison.md` positions autumn-harvest against the five durable-execution engines an architect is most likely to shortlist alongside it — **Temporal, DBOS, Inngest, Hatchet, and Restate** — so an evaluator can reach a defensible include/exclude decision in one sitting without cross-referencing five vendors' marketing pages. Written in an engineering-comparison, credibility-first tone: it names harvest's own gaps plainly rather than only its strengths.

**Structure:** an at-a-glance matrix (engines as columns) plus **11 per-dimension detail tables** covering every AC1 dimension × 6 engines — required infrastructure, self-host complexity, language/SDK support, programming model, determinism guarantees & tooling, versioning/safe-deploy, scheduling depth, observability surface, HA/multi-region, managed-cloud availability, and license. Three differentiator narratives (Postgres-only operations; determinism safety in depth; embedded-in-your-web-app deployment). A **"Where harvest is behind"** section naming 8 concrete gaps (Rust-only SDK, single-region/no multi-region DR, no managed cloud, Postgres-only/no pluggable persistence, incomplete Vantage UI parity, younger ecosystem, no cross-shard workflows, no first-party benchmarks). A **"Choose something else if…"** paragraph per competitor.

**Evidence discipline (the falsifiable part):** every harvest _shipped_ capability cell carries a resolving phase entry and/or `#issue` link (e.g. build-ID routing #171 + percent ramp #604, `WorkflowReplayer` Phase 3.5, ND-block #603, schedules #240/#241/#337/#484/#478/#543/#350/#534/#771/#488/#499/#607, MCP tools #597, deterministic primitives #384, sessions #606, timeline #739, DAG run graph #690, health summary #679). **Planned** items are labelled as such against open issues (non-Rust SDK #959/#955, cross-region DR #954, data-residency shard pinning #697, benchmarks #941). Competitor cells are sourced from each vendor's public docs (linked inline), stamped **"accurate as of 2026-07-14"**, phrased neutrally, and flag anything **(unverified)** rather than papering over it; a maintenance note commits to revisiting the page each minor release.

**Cross-linking:** linked from `README.md` (the "Why" intro) and `docs/getting-started/README.md` (the "Where to go next" index). Forward-references the planned Temporal migration guide (#947) with a note that the reverse link lands when that page ships — the bidirectional cross-link is currently forward-only because the migration guide does not exist yet. All internal relative links verified to resolve against real files.

**No code, no event-schema surface, no `WorkflowEvent` variant, no migration, no route/contract change, no replay/determinism impact** — a single new docs page plus two one-paragraph link insertions.
