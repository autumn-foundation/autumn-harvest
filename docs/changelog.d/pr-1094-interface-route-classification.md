## Tooling — Classify `GET /workflows/registered/{name}/interface` in audit route lists (PR #1094)

Healed a RED `trunk-dev`: a merge-burst gap left the plugin's `contract_regression::every_management_route_is_classified` test failing on every trunk-based branch. PR #1092 added the read-only route `GET /workflows/registered/{name}/interface` to the plugin's `management_api_routes()` but never classified it in `autumn_harvest::audit`, and that test enforces that every `management_api_routes()` entry has a `CLASSIFIED_ROUTES` entry (issue #776 AC4 read-only enforcement source of truth). Classified the route `ReadOnly`, exactly mirroring its existing sibling `GET /workflows/registered/{name}/schema`, across all four audit lists in `autumn-harvest/src/audit.rs`: `CLASSIFIED_ROUTES` (`RouteClass::ReadOnly`), `EXCLUDED_ROUTES` (read, no audit trail), `ALL_MUTATION_ROUTES` (op `None`), and the `newly_classified_reads_are_read_only` pin test. `CLASSIFIED_ROUTES.len()` and `ALL_MUTATION_ROUTES.len()` stay balanced (one entry added to each), so `classified_routes_count_matches_route_manifest` still holds. No production code or runtime behavior change beyond making the already-shipped route reachable by a read-only principal and excluded from audit, consistent with the `/schema` sibling. No new `WorkflowEvent` variant, no migration.
