## Phase 4 — Vantage UI: DAG run-graph page (issue #957) + execution timeline/Gantt page (issue #960) (PR #1085)

Adds the two remaining Phase 4 Vantage dashboard pages, both server-rendered inline SVG in `autumn-harvest-plugin/src/ui.rs` (the Workers #142 / DLQ #226 precedent — no JS, no client-side charting library), both read-only except one already-audited mutation. **No new backend endpoint, no new `WorkflowEvent` variant, no migration, no core change.** The only `api.rs` touch is a shared-impl extraction (below). Diff confined to `ui.rs`, `api.rs`, and `tests/ui_integration.rs`.

### DAG run-graph page (issue #957)

- New DAG run-graph rendered on the per-DAG detail page (`GET /api/harvest/dags/{dag_name}`). `dag_detail_ui` now derives topology, per-node status, and timings **solely** from `dag_graph::build_run_graph` — the same in-process derivation the #690 API handler calls — so the picture and the #366 retry action can never disagree about what "failed" means. The previous UI-side status fork (`map_node_states`/`DagNodeState`/`dag_node_state_label`/`merge_dag_task_state`/`infer_skipped_node_state`/`parse_dag_skip_marker_index`) is **deleted** (its unit tests deleted with it; grep for every symbol is empty), satisfying #957's "must not fork its own node-status derivation" AC.
- Topology renders as level-by-level inline SVG (`build_graph_layout`, one `<line>` per `depends_on` edge), each node filled **and** icon-marked per status (`succeeded`/`failed`/`timed_out`/`cancelled`/`running`/`pending`/`skipped`) so status is distinguishable without color (accessibility), with `role="img"`+`aria-label` and per-node `<a>`/`<title>`. Node index alignment (`nodes[i]` ↔ `tasks()[i]` ↔ `execution_levels()`, all from one `DagDefinition`) is pinned by a regression test. Geometry is fully clamped/guarded — no panics on zero-node, cyclic-impossible, or huge-fan-out runs; ≥ 200 nodes fall back to a scrollable container.
- Click-through node detail panel shows `status`/`started_at`/`finished_at`/`attempts`/`error_type` + truncated error first line. A failed node offers **"Retry from this node"** whose confirmation names the exact widened node set (#366's level + downstream-closure semantics) before commit.
- **`api.rs` change (the only one): `retry_dag_run`'s handler body extracted into `pub(crate) retry_dag_run_inner` + `DagRetryFailure` (with `human_message` + `into_http_response`).** The HTTP `retry_dag_run` handler delegates to it, preserving the #366 wire contract byte-for-byte (every original status/body arm reproduced). The UI dry-run confirm and the commit both call the same audited `retry_dag_run_inner` (`OP_DAG_RETRY`, `source = SOURCE_UI`); the whole `/dags/{dag_name}/runs/{run_exec_id}/retry` route (GET confirm + POST commit) is `require_admin`-gated to match the API, so the UI adds no unaudited mutation path.
- **Behavior changes:** classic (non-unified) DAG runs — which #690 rejects with `400` — now render the explicit "no topology available for classic DAG runs" degraded message (required to source statuses solely from `build_run_graph`); and an explicitly-provided-but-unknown `?run=` now returns the 404 message (AC7) instead of silently falling back to the first valid run (an omitted `?run=` still defaults to the latest run).

### Execution timeline / Gantt page (issue #960)

- New **Timeline** tab on the execution detail page (route `GET /workflows/{id}/timeline`, read-only, non-admin — parity with the #739 API). `workflow_timeline_ui` calls `derive_timeline` in-process (the same shipped #739 function — not a forked history-derivation).
- Renders one horizontal span per step on a shared wall-clock axis, lane-grouped by `step_kind`, colored by `outcome`, with the `wait_ms`/`exec_ms` split drawn as two segments **only when #739 provides it** (a single undivided span otherwise — never fabricating a split). Gantt geometry is clamped/guarded (`x_scale` clamps to axis width; `GanttAxis::new` forces `end > start`; zero/open spans use a min-width; casts are bounded) — no panics on never-started, still-running, clock-skew, or null-split histories; in-flight steps render as open-ended spans to "now".
- Uniquely versus every competitor, engine interventions render as first-class bands because those states are durable columns: operator **pauses** (#383) render as a full-height shaded band with reason/actor (active pause only); **ND-blocks** (#603) render as a distinct marker with the block reason. The rollup header shows `total_wall_clock_ms`/busy/wait and highlights + scroll-focuses (`#slowest`) the slowest step. Runs > 500 steps truncate with a note.
- The nondeterminism-block runbook is surfaced as non-clickable `code` text (a repo path, not a served URL — matching the `docs/runbooks/safe-deploy.md` convention), never a dead relative `<a href>` that would 404 during triage.

### Deferred #739/#690 data gaps (honored, not patched with a UI-side history parse)

Per both issues' "file the gap against the data API, never patch in the UI" clause, four ACs are honored only to the extent the shipped derivations expose data, each recommended as a #739 follow-up: (1) per-span deep-links (#960 AC7) — a `TimelineStep` carries no child/activity exec_id; (2) adjacent-attempt spans (#960 AC3) — a step has an `attempt` count but no per-attempt timestamps, so retries render as one span + `×N` badge; (3) historical/resolved pause windows (#960 AC4) — `StepKind` has no `Pause` variant and the row keeps only the active pause; (4) interactive axis zoom (#960 AC8) — deliberately no-JS, min-span-width compression only. Analogously, #957 AC3's "link to underlying task/activity detail where one exists" is honored by the "where one exists" conditional (the #690 `DagRunNode` carries no per-node exec_id, so no link target exists).
