## Phase — Assay #11 rerun on 0.7.0 at every depth, and 0.7.0 benchmarks (issue #1972)

Assay ledger #14 reruns assay #11 against 0.7.0. The pre-registration
(`docs/rnd/2026-10-08-harvest-vs-temporal-0.7.0-depth-sweep-preregistration.md`)
was committed and pushed before any run.

**Matrix.** Three trees: `0aeb887` (0.7.0, the base of PR #2052), `513b7aa`
(its head, with the #1971 claim fix) and `9f444b7` (`trunk-dev`). Arms
`postgres`, `redis_pg` and `temporal_go` (Temporal 1.25.2, assay #11's binary).
Depths 250, 500, 1,000 and 2,000, three rounds each. All 84 runs are valid.

**Result.** On 0.7.0 the default mode is 1.78x to 7.17x behind Temporal, and
the Redis mode 1.74x to 2.10x. With the #1971 fix, the default mode holds 21.1
to 22.1 workflows/sec at every depth, and the gap is 1.16x to 1.36x. Lines L1
and L2 kill; L3, L4 and L5 pass. The #1815 signals name the claim as the
bottleneck. Post hoc, the claim loop runs at 0.91 to 0.99 occupancy.

**Apparatus.** `docs/assays/apparatus/0014-harvest-vs-temporal-0.7.0/` holds
the harvest harness, the sweep driver and `grade.py`. A capture recorder keeps
the per-event #1815 signals and returns `is_enabled() = false`, so no sampler
SQL runs. Review found that assay #10's Redis residue probe never matched the
hash-tagged dispatch keys. This harness reads both key families.

**Benchmarks.** `docs/benchmarks/results-v0.7.0.md` publishes the 0.7.0
end-to-end sweep, taken on `9f444b7` with one native cluster per shard: 15.46
workflows/sec at one shard. `PUBLISHED_BASELINES` and
`PUBLISHED_RESULTS_VERSION` follow. The 0.6.0 file stays. The host differs from
0.6.0's, and the results file carries a same-box 0.6.0 control.

**Docs.** `docs/comparison.md` cites assay #14 in place of its "no cell on this
page" disclaimer. `docs/benchmarks.md` carries the 0.7.0 headline and points at
the assay without naming the engine (#1309).

**Guards.** `assay_rerun_docs` pins the pre-registration, every registered
cell, ledger row 14 and the citation. `benchmarks_docs` pins the headline
version and keeps every earlier release linked. `doc-claim-drift.py` pins the
old disclaimer as stale.

No engine change: no `WorkflowEvent` variant, no migration, no public API
change.
