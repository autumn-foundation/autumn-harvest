## Remove exhausted local activities from the stack endpoint's pending list (PR #1022, issue #773)

**Production fix** (implemented): follow-up to the same-PR fix that made the `pending_local_activities` fold in the workflow `/stack` endpoint (`autumn-harvest-plugin/src/api.rs`) correctly *insert* `LocalActivityScheduled` entries (by reading `activity_id`/`name` under `.data`). Correctly inserting entries activated a latent bug flagged in a Codex P2 review: the fold's SQL filter selected only `LocalActivityScheduled`/`LocalActivityCompleted`/`LocalActivityFailed`, and its remove arm only removed on `LocalActivityCompleted`, so it never consumed the terminal `LocalActivityExhausted` event (issue #773's retry-budget-exhaustion close).

**Root cause**: a local activity that exhausts its retry budget records `LocalActivityScheduled + N×LocalActivityFailed + LocalActivityExhausted` and no `LocalActivityCompleted`. If the workflow *catches* that terminal failure and keeps running (the `/stack` endpoint is for RUNNING workflows), the exhausted activity stayed in `pending_local_activities` forever — the entry was inserted on `Scheduled`, kept across each `Failed` (correctly — a *bare* mid-retry `LocalActivityFailed` must stay pending per #773), and never removed because `LocalActivityExhausted` was neither loaded by the SQL filter nor matched by the remove arm (it fell through the catch-all).

**Fix**: add `LocalActivityExhausted` to the SQL `eq_any` filter and to the remove arm alongside `LocalActivityCompleted` (both are terminal closes → remove the pending entry). The `activity_id` is extracted under `.data` by the fold's existing generic pre-match read, so no per-event extraction change was needed. The `LocalActivityFailed` handling is deliberately unchanged — a bare mid-retry `Failed` still stays pending (asserted by `stack_pending_local_activity_surfaces_last_failure`). No public API change, no type/signature change, no new `WorkflowEvent` variant, no migration.

**Verification**: TDD red→green against a fresh local Postgres 16 per test — the new `stack_exhausted_local_activity_is_not_pending` (`autumn-harvest-plugin/tests/read_path_decode_integration.rs`, seeding a RUNNING workflow with `Scheduled + Failed + Exhausted` for one `activity_id`) FAILS without the remove-arm change (exhausted activity wrongly pending) and PASSES with it; the full `read_path_decode_integration` suite is green (21/21, including `stack_pending_local_activity_surfaces_last_failure`). Local CI mirror for the touched crate: `cargo fmt --check`; `clippy -p autumn-harvest-plugin -D warnings` (default, `mcp,unified-dag-execution`, and `metrics` feature combos); `cargo test -p autumn-harvest-plugin --lib` = 513 passed. CI runs the Docker-backed `read_path_decode_integration` suite on Linux.
