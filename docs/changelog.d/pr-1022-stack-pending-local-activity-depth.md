## Fix stack endpoint's pending-local-activity fold reading fields at the wrong JSON depth (PR #1022, issue #773)

**Production fix** (implemented): the `pending_local_activities` fold in the workflow `/stack` endpoint handler (`autumn-harvest-plugin/src/api.rs`) read `activity_id` and `name` from the **top level** of `harvest_events.event_data`, but that column stores the full adjacently-tagged event envelope `{"type": ..., "data": {...}}`, so an event's own fields live under `.data`, not at the top level.

**Root cause**: the top-level `.get("activity_id")` was always `None`, so every `LocalActivityScheduled`/`LocalActivityCompleted`/`LocalActivityFailed` event fell through the fold's catch-all arm and nothing was ever inserted — `pending_local_activities` was always `[]`. The `type` key was read correctly (it genuinely lives at the top level of the envelope; the fold actually uses the DB `event_type` column here), so only the two `.data`-nested fields were at the wrong depth. The sibling failure-map query in the same handler already decodes via `serde_json::from_value::<WorkflowEvent>(data)` and was unaffected.

**Fix**: read `activity_id` and `name` under `.data` (`event_data.get("data").and_then(|d| d.get("activity_id"))`, and the analogous read for `name`). This restores the issue-#773 behavior that a backing-off/flapping local activity surfaces its `last_failure` on the `/stack` response. The test `stack_pending_local_activity_surfaces_last_failure` (`autumn-harvest-plugin/tests/read_path_decode_integration.rs`) now passes; it was masked on `trunk-dev` because CI fail-fast aborted the read-path-decode suite before reaching it when the earlier typed-failure (issue #767) INIT_SQL step failed. No public API change, no type/signature change, no new `WorkflowEvent` variant, no migration.

**Verification**: reproduced deterministically and confirmed the fix against a fresh local Postgres 16 — the single test passes ×3 (fresh DB each) and the full `read_path_decode_integration` suite is green (20/20, no sibling regression). Local CI mirror for the touched crate: `cargo fmt --check`; `clippy -p autumn-harvest-plugin -D warnings` (default, `mcp,unified-dag-execution`, and `metrics` feature combos); `cargo test -p autumn-harvest-plugin --lib` = 513 passed; a representative subset of the plugin integration test targets compile-checked green (full `--no-run` of all ~60 fat static test binaries exceeded the sandbox disk budget, not a compile issue). CI runs the Docker-backed `read_path_decode_integration` suite on Linux.
