Resolved by the #543/#593/#609 reconciliation precedent: map the ACs onto the shipped prior art and close only the genuine gaps. **New `docs/rnd/sqlite-feasibility.md`**, framed honestly as a **retrospective decision record** (the report trails the productization it justifies — stated in the first paragraph rather than buried, and recorded as a process lesson: the written deliverable should gate the productization issue, not trail it). Contents: a one-page decision summary; a **Coupling mechanisms** table (seven mechanisms — Diesel query layer 42 modules, `SKIP LOCKED` 13, `INTERVAL`/`make_interval` 8, `pg_advisory_xact_lock` 7, `to_regclass` 6, `LISTEN`/`NOTIFY` 4, `gen_random_uuid` 1 — plus the 83 Postgres-DDL migrations); the **exhaustive 43-row module-by-module inventory** (43 of the 93 core modules are coupled) with every row classified **(a)** trivially trait-able (18) / **(b)** needs a semantic substitute (7) / **(c)** fundamentally Postgres-shaped, i.e. portable only by dropping a capability or reimplementing wholesale (18); a costed sizing of the never-built `StorageBackend` seam; its estimated **cost to the Postgres path** (dynamic dispatch on the benchmarked claim hot path, loss of the fused single-statement claim query, an abstraction layer between the hardest bug class in the codebase and the SQL it reasons about, and a doubled test matrix that is mostly meaningless skips); the **test-suite portability** split (replay/event-schema → ported; single-execution lifecycle → ported with substitutes; multi-worker contention → *semantically void*, not merely hard; fleet/operational surfaces → out of model); the **go/no-go recommendation** (**go, as a separate companion crate — option ii — not a core trait**, which is what shipped) with its known capability losses; **hub-handoff scoping only** (edge `ExecutionId` shard semantics, `(workflow_name, workflow_id)` conflict rules for two disconnected nodes starting the same id, and replay fidelity on ingest — with export-only archival named as the credible first cut); a paragraph on **other embedded backends** (libSQL/Turso as the strongest adjacent option since it is file- and wire-compatible and could relax the single-writer constraint; DuckDB declined as an OLAP engine mismatched to high-frequency point writes; `sled` declined); and the **timebox** with the method note. **Load-bearing finding surfaced by the audit:** two modules (`store`, `concurrency`) reference `SKIP LOCKED` **only in comments** — they *consume* the claim invariant without issuing the SQL, so a `StorageBackend` trait derived mechanically from SQL call sites would have abstracted the invariant's *writers* and silently orphaned its *consumers* (compiles, passes unit tests, wrong under concurrency). That is the empirical reason the classification is a human judgement rather than a generated table. **Anti-rot enforcement (the TDD deliverable):** new no-DB guard suite `autumn-harvest/tests/integration/sqlite_feasibility_docs.rs` (8 tests) makes the report's "exhaustive … verifiable against a `grep`-level audit" claim **falsifiable** instead of aspirational — it re-derives the coupling inventory from `autumn-harvest/src/*.rs` at test runtime (never a hardcoded module list, which would rot identically to the prose) and asserts bidirectionally that every detected module is inventoried (failing with a **paste-ready table row** naming the new module and its mechanisms), that no row names a module that no longer exists or is no longer coupled, that every row carries an explicit (a)/(b)/(c), that every row names the mechanisms grep actually finds for it, that the per-mechanism counts quoted in the report match a live grep, that the cited cross-backend replay test (`sqlite_history_replays_on_core_replayer`) actually exists, and that the zero-regression invariant is *structurally* true (core has no `rusqlite` and no `autumn-harvest-sqlite` dependency; the SQLite crate depends on core with `default-features = false`). The detector is deliberately **precise, not generous**: a bare `INTERVAL` matches Rust constants such as `DEFAULT_WORKER_POLL_INTERVAL` and a bare `diesel` matches the guardrail lint's own prose listing forbidden crates — four modules (`effective_config`, `guardrail`, `history_export`, `wasm_activities`) are false positives under a loose detector and are correctly excluded, since an inventory padded with noise would discredit the report as badly as one with holes. Deliberately **not** guarded: the report's prose judgements (seam sizing, cost estimates, go/no-go reasoning) — those are argument, not fact, and freezing them would stop the document being revisable. Every guard was mutation-verified (drop a row / add a phantom row / stale a count / strip a classification / drop a mechanism from a row → each caught by exactly one guard, 7 passed 1 failed; plus a simulated new coupled module landing in `src/`). **Docs + tests only — zero production code touched** (no core, no plugin, no `autumn-harvest-sqlite` source), so the "zero behavior/perf regression to the default Postgres build" invariant holds by construction; **no new `WorkflowEvent` variant, no migration, no route/contract change, no replay/determinism impact.** No CI manifest change needed — the pre-existing `allos autumn-harvest integration testing -` row runs the whole no-DB target on all three OSes, so the new module is wired by its `mod.rs` registration alone.
