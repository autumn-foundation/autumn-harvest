## Phase 4 — Replay tolerates interleaved sibling terminals in forward-scan matchers (issue #1071)

Fixed a pre-existing **core** replay limitation (shared by the Postgres engine, surfaced by the SQLite backend work #1068/#1069): an *ideal, correct* workflow history that interleaves a sibling terminal event next to the event a matcher is scanning for would falsely fail replay with `NonDeterminismDetected(EarlyCompletion)`. The canonical case is a timer-first mixed suspension batch — `tokio::join!(ctx.timer(...), ctx.execute_activity(...))` with the timer command emitted first — recording `WorkflowStarted, TimerStarted, ActivityScheduled, ActivityCompleted, TimerFired`: `HistoryMatcher::match_timer_strict`'s forward `TimerFired` scan **broke at the still-unconsumed `ActivityScheduled`**, never recognized the timer as fired, skipped the re-arm, and diverged. The mirror `join!(activity, timer)` (activity first) happened to replay fine.

**Fix (matcher-scan logic only, in `impl HistoryMatcher`, `autumn-harvest/src/replay.rs`):** each intolerant forward-scan matcher now tolerates an interleaved sibling terminal at its recorded position — the same non-consuming-skip / rewind template `match_signal_or_timer` (#476) already uses — across all four documented manifestations:

- **`match_timer_strict`** — a rewind arm for interleaved unconsumed sibling *commands* (`ActivityScheduled | LocalActivityScheduled | MarkerRecorded | SideEffectRecorded`) plus transparent non-consuming skip arms for interleaved sibling *terminals* and *foreign `TimerFired`* (a `TimerFired` whose id ≠ this timer's belongs to a sibling). Fixes manifestation #1 (timer-first mixed batch) and #4 (reversed multi-timer same-batch fire order).
- **`scan_activity_terminal`** — added `LocalActivityScheduled` to the interleaved-command arm and a transparent skip for `TimerFired (any id) | ChildWorkflow{Completed,Failed} | LocalActivity{Completed,Failed}`. Fixes manifestation #2 (sibling timer fires before an activity's terminal).
- **`match_signal`** — transparently crosses a sibling deadline timer's `TimerStarted`/`TimerFired` recorded ahead of the awaited signal; a reserved `__signal_timeout:{seq}:{name}` timer (a concurrent `receive_signal_timeout` race, #476) is crossed without a rewind so the signal-win advances the cursor past it (no false `EarlyCompletion`), while a genuine user `ctx.timer` sibling keeps its rewind. Fixes manifestation #3 (deadline timer fired before an awaited plain-wait signal).

**Contract-preserving by construction: no new `WorkflowEvent` variant, no migration, no change to event emit / suspension-batch command ordering** — the persisted contract is untouched; this only changes how the matcher *reads* an existing history. Foreign events are never marked consumed, so each crossed sibling stays claimable by its own matcher in program order.

**Tolerance does not over-swallow — genuine non-determinism still diverges:** guarded by `interleaved_sibling_multi_timer_wrong_one_fires_still_diverges`, `interleaved_sibling_signal_stray_timer_fired_still_diverges`, `interleaved_sibling_signal_stray_timer_started_still_diverges`, the matcher-unit `matcher_signal_scan_parks_on_lone_open_deadline_timer` (a lone open deadline timer parks rather than being falsely nd-blocked), and the retained `replay_activity_history_for_timer_workflow_detects_timer_mismatch` (a genuine timer-id mismatch still diverges via the untouched positional anchor).

**Known limitation (pinned + documented):** composing a plain `wait_for_signal` with a cancellable timer (#768) in one `join!` where the cancellable `TimerFired` is recorded before the `SignalReceived` still diverges on strict replay (self-heals live; use `ctx.receive_signal_timeout` #476 for the supported signal-or-deadline shape) — pinned by `known_limitation_signal_wait_composed_with_cancellable_await_fire_diverges_on_reversed_order`.

**Cross-crate pin flip:** one now-obsolete `autumn-harvest-sqlite` known-limitation control (`reversed_timer_fire_order_breaks_core_replay`) is renamed to `reversed_timer_fire_order_replays_on_core_after_1071` with its assertion flipped from `NonDeterminismDetected` to `ReplaySucceeded` — the core fix makes that reversed multi-timer history replay-succeed, so the stale pin would otherwise fail the `cargo test -p autumn-harvest-sqlite` CI step. No sqlite workaround *logic* changed (the `arm_seq` fire-order tie-break is retained but is no longer a replay-*correctness* prerequisite). The sqlite `join!(activity, timer)` "activity branch first" and plain-`wait_for_signal`-with-deadline guidance become unnecessary and are flagged for a follow-up docs cleanup (not changed here); the WASM branch #1072 inherits the same core matcher.

Tests: `autumn-harvest/tests/integration/replayer_tests.rs` gains the four manifestation replay-succeeds tests (`interleaved_sibling_timer_first_mixed_batch_replays_succeeded`, `interleaved_sibling_timer_fires_before_activity_terminal_replays_succeeded`, `interleaved_sibling_signal_after_deadline_timer_fired_replays_succeeded` + `interleaved_sibling_signal_after_plain_user_timer_fired_replays_succeeded`, `interleaved_sibling_multi_timer_reversed_fire_order_replays_succeeded`), the child-workflow coverage variant `interleaved_sibling_child_workflow_terminal_before_timer_replays_succeeded`, the divergence guards above, and the known-limitation pin; `replay.rs` gains the `matcher_signal_scan_parks_on_lone_open_deadline_timer` unit test. CI reproduced at cargo 1.97.0: integration `960 passed`, all-features lib `2071 passed`, clippy `-D warnings` + fmt clean, sqlite `125/125`.
