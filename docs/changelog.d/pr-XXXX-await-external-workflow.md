## Phase 3.5x — Durable await of external workflows (`ctx.await_external_workflow`) (issue #757)

`ctx.await_external_workflow::<T>(target: ExecutionId) -> HarvestResult<T>` (typed) and `ctx.await_external_workflow_value(target) -> HarvestResult<Value>` (untyped) let a running workflow durably block until an arbitrary, independently-started sibling execution reaches a terminal state, then hand back its typed result or terminal cause. It is the third verb of the external-workflow family (signal #244 / cancel #492 / **await #757**), a close architectural mirror of the cancel primitive. Callable from any `#[workflow]` body with **no feature flag**.

**Semantics** (the key differences from cancel #492): target `COMPLETED` → resolves with the **deserialized output**; target `FAILED`/`TIMED_OUT`/`CANCELLED`/`TERMINATED` → returns a typed `Err` carrying the target's terminal cause as an **outcome** (not a transport error) — a `FAILED` target surfaces as `HarvestError::WorkflowFailed { name: "external-workflow:{target}", .. }`, the SAME typed error a failed child surfaces as (issue #767), so `err.workflow_error_type()`/`workflow_details()`/`is_workflow_non_retryable()` are all readable; target `RUNNING`/`PAUSED` → the caller parks durably and resolves within one outbox poll interval after the target reaches any terminal state; **self-await** (`target == own ExecutionId`) → immediate `HarvestError::ExternalAwaitFailed { reason_code: "self_await" }`, records no history (nil-UUID sentinel); an **unknown target** still unknown after the configured grace window → `HarvestError::ExternalAwaitFailed { reason_code: "target_unknown" }` (a transport failure, distinct from the terminal-cause outcomes; `err.external_await_reason_code()` reads it). Await is **observe-only** — it never establishes parent/child linkage, cancels, triggers `ParentClosePolicy`, or has any lifecycle effect on the target.

**No new migration.** Three new append-only `WorkflowEvent` variants appended at the **END** of the enum (opaque adjacently-tagged JSON; pre-upgrade histories deserialize/replay unchanged): `ExternalAwaitRequested { await_id, target }`, `ExternalAwaitResolved { await_id, output }` (carries the target's inflated output), `ExternalAwaitFailed { await_id, reason_code, message?, error_type?, details?, non_retryable? }` (the optional typed fields are `#[serde(default, skip_serializing_if = "Option::is_none")]`; carry the target's typed `WorkflowFailure` for a `FAILED` target). New `ExternalAwaitId(Uuid)` newtype (exact clone of `ExternalCancelId`, re-exported from `lib.rs`), new `HarvestError::ExternalAwaitFailed { await_id, target, reason_code }` transport variant + `external_await_reason_code()` accessor.

**Implementation mirrors the cancel primitive throughout.** `replay::HistoryMatch::ExternalAwaitInProgress`/`ExternalAwaitFailed` variants + `StashedExternalAwait`/`StashedAwaitTerminal` stash + `pending_external_awaits` field; `HistoryMatcher::match_external_await(target)` (returns `Matched { output }` carrying the real output value); the await event triplet is stashed transparently in all ten scan loops (`scan_activity_terminal`, `scan_local_activity_terminal`, `drain_early_signals`, `match_external_activity`, `match_external_signal`, `match_timer_strict`, `timer_scan_cross_or_stop`, `match_signal`, `match_signal_or_timer`, `match_child_or_timer`) plus the `match_external_cancel` sibling scan and the two `matches!` skip-lists, and tracked in `has_buffered_history`/`has_non_lifecycle_unconsumed`. `WorkflowContext::await_external_workflow(_value)` + `dispatch_await_command` (suspension whose value is recovered from the appended terminal event on the resumed drive, never the channel). `WorkflowCommand::AwaitExternalWorkflow` dispatched through the worker's generalized `SignalBatchItem::Await(AwaitExternalWorkflowRun)`: `extract_signal_external_workflow`/`split_mixed_signal_batch`/`resolved_external_ids`, all classification guards (`should_requeue_signal_wait`, `extract_started_timer_for_suspension`'s valid-command set, the mixed-batch `is_mixed`/`any(...)` guards, the pure-external `all_resolved`+reconstruct), and `persist_signal_wait_park`'s post-park self-wake re-check. `persist_external_signal_inline` Await arm resolves a **same-shard** target inline via the new `execution::read_external_await_outcome` (which follows a `CONTINUED_AS_NEW` chain to the true terminal, reads the target's `WorkflowFailed` event for the typed cause, and is **observe-only** — never mutates the target or creates linkage); a cross-shard or still-running target leaves the bare `ExternalAwaitRequested` and re-parks. `timeout::enforce_external_awaits_outbox` (folded into `enforce_timeouts_once` right after the cancel outbox) resolves cross-shard + still-running targets, applying the grace-window `target_unknown` rule (mirrors `enforce_external_cancels_outbox`). The resolved output is stored **INFLATED** (not offloaded) into the awaiter's own history in both the inline and outbox paths — correct, replay-deterministic, and free of any awaiter-owned blob-GC hazard (an offload-aware awaiter copy is a possible future optimization). `testing.rs`: `WorkflowTestEnv::with_external_await_result`/`with_external_await_failure` + a `process_command` Await arm, a `WorkflowSimulator` arm, and `NonDeterminismKind::ExternalAwaitMismatch` (+ `classify_kind` `"external await"` arm, also closing the cancel gap).

**No metric added** (optional per the issue). Example: `autumn-harvest/examples/await_external_workflow.rs` (a fan-in coordinator awaiting three independently-started legs by id in one line each, branching on a leg's typed terminal cause). Tests: event round-trip + pre-#757 back-compat unit tests in `event.rs`; 6 `match_external_await` matcher unit tests in `replay.rs` (incl. the concurrent-with-activity stash regression); 6 context unit tests (live-command, self-await-no-history, replay-resolved, replay-failed-typed-`WorkflowFailed`, replay-`target_unknown`, ND-wrong-target); 3 `WorkflowTestEnv` coverage tests; 5 `WorkflowReplayer` fixtures in `tests/integration/replayer_tests.rs` including the falsifiable **1000-pass determinism** bar (mirroring the #476 precedent), a failed-target typed-branch fixture, a concurrent-with-activity fixture over both interleaved orderings, and an `ExternalAwaitMismatch` detection fixture; 7 DB integration tests in `tests/integration/cross_workflow_await_tests.rs` (completed-inline → Ok, failed-target → typed error surfaces, running-then-outbox-resolves, cross-shard via outbox, self-await immediate-Err-no-park, unknown-target grace-window, observe-only-target-unchanged) — **run green against real Postgres 16** and wired into `.github/ci/integration-suites.txt`.
