## Phase 3.51 — Read-only operator role for least-privilege triage access (issue #776)

Promotes `autumn_harvest::audit`'s route classification from "used for audit" to also "used for authz": a **read-only operator role** an embedder enables in **one builder call**. A principal the embedder marks read-only reaches **100%** of `RouteClass::ReadOnly` routes but receives **403 Forbidden** on **every** `Mutating` route — for exposing triage/status dashboards to support/on-call users without granting the mutate-everything credential, replacing "write a custom reverse proxy" with a single call.

**Enforcement = one opt-in, class-aware tower layer** (`enforce_read_only_class`, `autumn-harvest-plugin/src/api.rs`) installed on `harvest_api_router` **only** under the new `HarvestPlugin::api_with_role_auth(path, middleware)`. Driven **purely** by `autumn_harvest::audit::CLASSIFIED_ROUTES` — the single source of truth, so there is no second hand-maintained mutating-route list to drift (AC3). Keys on `request.method()` + the nest-stripped `request.uri().path()`, matched via **`matchit`** (the radix-tree matcher axum itself uses) built once into a per-method `HashMap<Method, matchit::Router<RouteClass>>` with **positional param normalization** (`{id}`→`{p0}`) so a single router accepts the full template set without a name conflict, preserving **static-beats-param precedence** (`POST /workflows/batch_start` is never mistaken for the `ReadOnly` `/workflows/{id}` — a privilege-escalation bug if wrong). Deliberately **not** `axum::extract::MatchedPath`, which is unreliable when read from a layer on a nested router (axum #1441) — the exact position this layer occupies. Classification keys on the route class, **never the HTTP verb**: the two `ReadOnly` POST routes (`POST /workflows/{id}/query/{query_name}`, `POST /admin/build-routing/retire`) are correctly reachable.

**Pure decision fn (core `audit.rs`):** `deny_readonly_mutation(is_readonly, class) -> bool` = `is_readonly && !matches!(class, ReadOnly | PublicSafe)`. **Fail closed by construction:** the matcher resolves an unmatched path / unknown method to `RouteClass::Mutating`, so a route a contributor forgot to classify is denied to read-only principals — never silently exposed (AC4). Pinned by a truth-table unit test.

**Read-only principal predicate (`has_harvest_readonly_access`):** true iff the autumn-web `Session` carries an explicit read-only marker (`role` ∈ {`harvest_readonly`,`harvest_operator`,`operator`,`readonly`,`read_only`} or a truthy `is_harvest_readonly`/`is_harvest_operator`) **and** no explicit admin marker (`role` ∈ {`admin`,`harvest_admin`} or truthy `is_harvest_admin`/`is_admin`). Admin marker present, no session, or no marker → `false` (full access — the read-only restriction is opt-in per principal, preserving existing boundary semantics; documented contract that the embedder must explicitly mark a principal read-only).

**Opt-in (`HarvestPlugin::api_with_role_auth`):** mirrors `api_with_auth` (sets `api_path` + the embedder auth middleware, which makes `admin_auth_boundary = true`) **and** sets a new `role_auth_enabled` flag on `HarvestApiState` (mirrored from the plugin builder in `build()`, same `Arc<Mutex<bool>>` setter/getter pattern as `set_decode_payloads_on_read`). In `build()`, when role-auth is enabled the class layer is installed on the combined router **before** the embedder middleware wraps it, so the request order is: embedder auth mw (sets `Session`) → class layer (enforce) → per-route `require_admin` (a no-op under the boundary) → handler. **Because `admin_auth_boundary = true`, per-route `require_admin` and the SSE in-handler admin check pass for the read-only principal → AC1 is satisfied with NO router/SSE surgery.** This is safe: the class layer 403s a read-only principal at the route boundary *before* any handler's in-handler admin write-gate runs, and every state-writing handler sits on a `Mutating` (or unclassified→fail-closed→`Mutating`) route. The only extra capability the boundary grants a read-only principal is **READS** (payload decode #608, the SSE event stream) — explicitly scoped out by the issue (verb restriction, not field/row restriction). **`api_with_auth` and the default `api(path)` mount are byte-for-byte unchanged (AC6):** the class layer is installed *only* under `api_with_role_auth`; `role_auth_enabled` defaults off.

**403, not 401 (AC2):** a read-only principal on a `Mutating` route gets `403 Forbidden` (`{"error":"read-only principal: mutation not permitted"}`), distinct from the anonymous `401` the admin gate returns, built directly (no dependency on an autumn-web `forbidden` helper). **Observability (AC7):** every denial emits `tracing::warn!(method, path, "harvest: read-only principal denied mutation (403)")`; a best-effort DB audit row is deliberately *not* written (the layer runs before a pooled connection is acquired; forcing a write on every probe would be a DoS vector). The stable 403 body marker is also a distinguishable signal.

**Classification scope (the largest work item):** 31 routes were mounted in `harvest_api_router` but had drifted without a `CLASSIFIED_ROUTES` entry — **8 Mutating** (`update-with-start`, `dag runs/{}/retry`, circuit `force-open`/`force-close`, `POST /admin/completion-triggers`, `POST /calendars`, `PUT /calendars/{name}`, `DELETE /calendars/{name}`) and **23 ReadOnly** (`batches/pending`, `workflows/registered`(+/`{name}`/schema), the two `workflows/by-id/{workflow_name}` 400-stubs, `workflows/types/{name}/handlers`, `dead-letters/aggregate`, `admin/circuits`(+/`{name}`), `admin/queues/scaling`, `admin/metrics`, `admin/completion-triggers` GET, `admin/schedules/{id}`(+/runs+/decisions+/preview), `admin/schedules/decisions`, `POST /admin/schedules/preview`, `calendars` GET(+/`{name}`), `workers/{id}/pinned`, `admin/queues/{queue}/eligibility`, `admin/tasks/{id}/eligibility`). Each Mutating handler was verified to write state; each ReadOnly handler verified not to (privilege-escalation guard). The 4 circuit/dag/update ops reuse pre-existing constants (`OP_WORKFLOW_UPDATE_WITH_START`, `OP_DAG_RETRY`, `OP_CIRCUIT_FORCE_OPEN`, `OP_CIRCUIT_FORCE_CLOSE`) that had never been registered in `AUDITED_OPERATIONS` — now wired, with `Some(op)` manifest entries; the calendar + completion-trigger CRUD (no op constant, audit wiring out of scope) use `None` + `EXCLUDED_ROUTES`. `CLASSIFIED_ROUTES` and `ALL_MUTATION_ROUTES` stay size-synced (137 each); the 3 router-only routes (`/handlers` + the two by-id missing-id stubs) were added to `management_api_routes()` and `docs/api-contract.json` so the coverage sweep and contract parity cover them.

**Deviation from the issue's literal wording:** AC8 says the change is "confined to the `autumn-harvest-plugin` auth/router layer", but `CLASSIFIED_ROUTES`/`ALL_MUTATION_ROUTES`/`AUDITED_OPERATIONS`/`EXCLUDED_ROUTES` live in the **core crate** `autumn-harvest/src/audit.rs`, so classifying the drifted routes necessarily edits core (const arrays + `#[cfg(test)]` tests). **No new `WorkflowEvent` variant, no migration, no replay-determinism impact, no `::autumn_harvest::` macro-path change** — so it is allowed, but the "plugin-only" claim is inaccurate (flagged for spec-owner review).

**Known limitation (documented follow-up):** the nested `/ui` sub-router's paths are not in `CLASSIFIED_ROUTES`, so under fail-closed enforcement a read-only principal receives 403 on `/ui`. Admins reach `/ui` unchanged. Classifying the UI routes so read-only principals can view (but not act through) the dashboard is a follow-up.
