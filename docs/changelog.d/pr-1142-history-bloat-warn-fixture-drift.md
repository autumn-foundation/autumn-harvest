## Tooling — Fix hand-rolled test INIT_SQL fixtures missing 20260716000000_harvest_workflow_history_bloat_warn migration (issue #1142)

**Tooling/testing** (implemented): The `20260716000000_harvest_workflow_history_bloat_warn` migration (issue #704, PR #1139) added a `history_bloat_warned_at` column to `harvest_workflow_executions`, but four deliberately hand-rolled, partial-schema `INIT_SQL`/`LEGACY_INIT_SQL` test fixtures (the exact allowlisted set in `migration_hygiene.rs`'s `ALLOWED_HANDROLLED_MIGRATION_INCLUDES`) were never updated to include it. `WorkflowExecution::as_select()`/`as_returning()` reference the column on every full-row read/insert-returning, so every test in the affected binaries that loads a `WorkflowExecution` row failed with `DatabaseError(Unknown, "column harvest_workflow_executions.history_bloat_warned_at does not exist")` — this had been silently red on `trunk-dev` since the migration merged, and every PR based on it inherited the failure regardless of what the PR itself changed. **No product-code behavior change.**

**Fixed the four allowlisted hand-rolled fixtures**, following the exact pattern already used repeatedly in the same files for structurally identical past migrations (`chain_execution_timeout`/`chain_deadline_at` #617, `legal_hold_*` #747, `start_source*` #740): `autumn-harvest/tests/integration/integration_e2e.rs` (both `INIT_SQL` — appended the migration's `include_str!` — and `LEGACY_INIT_SQL` — appended the matching raw `ALTER TABLE ... ADD COLUMN IF NOT EXISTS history_bloat_warned_at TIMESTAMPTZ NULL;`, since the legacy-upgrade test's full-row insert/read-back touches it too), `autumn-harvest-plugin/tests/schedule_update_integration.rs`, and `autumn-harvest-plugin/tests/timeline_integration.rs` (both plugin fixtures patched with the same raw `ALTER TABLE` line alongside their existing hand-patched columns). The fifth allowlisted entry, `autumn-harvest-plugin/tests/outbox_integration.rs`, needed no change — its hand-rolled `OUTBOX_INIT_SQL` is a separate, unrelated app-DB `harvest_workflow_outbox` migration, and its harvest-DB side already uses the paved-path `full_migrations_sql()` helper (issue #1031/#1045), which can never drift.

**Full repo sweep confirmed no other affected files**: a whole-workspace search for `include_str!(...up.sql...)` and `ADD COLUMN IF NOT EXISTS` found exactly these four fixtures plus `admission_gate_authoritative_tests.rs` (already on the paved path with an unrelated small patch) and the guard/doc-comment references in `migration_hygiene.rs`/`build.rs`/`schema.rs`. `rate_limit_key_tests.rs` and `workflow_retry_tests.rs` (also named in the issue as failing) needed no direct edit — both borrow `integration_e2e::setup_test_database_url_or_env`, so fixing `integration_e2e.rs`'s bundle fixes them transitively. `autumn-harvest-cli`, `autumn-harvest-redis`, and the `examples/` crates have no hand-rolled DB fixtures of their own.

**No new CI wiring needed**: `integration_e2e`, `rate_limit_key_tests` (filter `rate_limit_key`), and `workflow_retry_tests` were already run-covered by `.github/ci/integration-suites.txt`; `timeline_integration` (plugin) was already run-covered; `schedule_update_integration` (plugin) remains separately-tracked, pre-existing allowlisted debt in `ci_run_coverage.rs` (`ALLOWLIST_DEBT_REASON`), unrelated to this fix and out of scope here.

**No new `WorkflowEvent` variant, no new migration, no route/contract change, no replay/determinism impact, no production-logic change** — test-fixture SQL only. **Follow-up (same PR, caught by CI on push): a second, independent instance of the identical drift class.** `Test (ubuntu-latest)` failed post-push with `dag_execution_timeout_tests::{scheduler_tick_applies_fleet_wide_execution_timeout_ceiling_to_dag, scheduler_tick_buffered_drain_threads_dag_declared_execution_timeout}` both erroring `Database("new row for relation \"harvest_schedules\" violates check constraint \"harvest_schedules_kind_check\"")`. Confirmed via `git merge-base --is-ancestor` that the introducing test commit (`8033bd5`, issue #743/PR #1141) predates this branch and is unrelated to this PR's diff; confirmed independent of the diff by reproducing the failure against the **already-#1142-patched** bundle on a fresh local Postgres 16 before applying this second fix. Fixed by adding the missing `include_str!` to both fixtures, immediately after the `20260430000000_harvest_workflow_schedules` include (the migration it directly follows and relaxes). `integration_e2e.rs`'s `LEGACY_INIT_SQL` needs no change — it never includes `20260430000000_harvest_workflow_schedules` at all, so the constraint (and its later relaxation) is out of scope for that fixture.
