## Decode stack `last_failure` only for surviving pending local activities (PR #1022, issue #773 / #608)

**Production fix** (implemented): follow-up to the same-PR fixes that made the `pending_local_activities` fold in the workflow `/stack` endpoint (`autumn-harvest-plugin/src/api.rs`) correctly *insert* `LocalActivityScheduled` entries and *remove* them on the terminal `LocalActivityCompleted`/`LocalActivityExhausted` close. Correctly activating the local-activity path surfaced a Codex P2 read-path-decode audit-fidelity bug: the fold decoded each entry's `last_failure` error **inline in the `LocalActivityScheduled` arm** — before a later terminal-remove arm could drop the entry.

**Root cause**: when the read-path decoder (issue #608) is admin-active and a still-RUNNING workflow has a local activity that failed with a stringified codec envelope and then EXHAUSTED (caught-and-continued), the Scheduled arm decoded and merged that failure into `decode_outcome` (touching the audit accumulator) before the `LocalActivityExhausted` arm removed the entry. The response then contained no such pending local activity, yet `audit_decoded_read` — which no-ops only on an *untouched* outcome — wrote a spurious `payload.decode_read` audit row (and could contribute to the decode-failure summary) for data that never left the handler. This violated the #608 contract "decode/audit exactly what is surfaced." The regular (task-queue) pending-activity `last_failure` path is unaffected: it decodes over already-surviving `harvest_task_queue` rows (there is no fold-and-remove), so it was left untouched.

**Fix**: defer `last_failure` decoding until after the fold. The `LocalActivityScheduled` arm now attaches the **raw (undecoded)** most-recent failure; once the fold has applied all terminal removals, a single post-fold loop over the **surviving** `pending_local_activities` decodes each entry's `error` inline and merges into `decode_outcome`. A removed entry's failure is therefore never decoded and never audited, while surfaced entries decode and audit exactly as before. Localized change — no restructure of the #608 decoder/audit plumbing, no behavior change for surfaced entries, no new `WorkflowEvent` variant, no migration, no public API/signature change.

**Verification**: TDD red→green against a fresh local Postgres 16 per test — the new `stack_removed_local_activity_failure_is_not_decoded_or_audited` (`autumn-harvest-plugin/tests/read_path_decode_integration.rs`, decode-enabled admin app; seeds a RUNNING workflow with `LocalActivityScheduled + LocalActivityFailed(envelope-error) + LocalActivityExhausted` for one `activity_id`) FAILS without the fix — a `payload.decode_read` audit row for `GET /workflows/{id}/stack` is written for the removed entry — and PASSES with it (empty pending list, no surfaced plaintext/envelope, zero decode audit rows). Full `read_path_decode_integration` suite green (22/22, including `stack_pending_local_activity_surfaces_last_failure` and `stack_exhausted_local_activity_is_not_pending`).
