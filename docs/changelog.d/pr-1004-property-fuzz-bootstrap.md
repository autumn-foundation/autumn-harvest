# Tooling — Property-based testing + cargo-fuzz harness bootstrap (PR #1004)

**Tooling/testing** (implemented): Bootstrapped a randomized-testing workstream with two complementary layers plus CI wiring — no product-code behavior change.

**Property tests** (`proptest`, foundation commit `be8aaa7`): a single external `autumn-harvest/tests/property/` target (mirrors the `tests/integration/` one-`mod.rs`-entry-point convention), bounded to 128 cases by default and overridable upward via proptest's native `PROPTEST_CASES` env knob, with on-disk `failure_persistence` disabled so CI runners stay artifact-free. Pure, non-`db`-gated suites (`policy_props`, `queue_fairness_props`, `task_duration_props`, `completion_trigger_props`, `completion_callback_props`, `event_serde_props`) run under `--no-default-features`; `db`-gated suites (`build_routing_props`, `dlq_props`) are `#[cfg(feature = "db")]` submodules that target **pure functions** in `#[cfg(feature = "db")]` modules and need no live Postgres. Coverage: `policy::compute_retry_delay` (cap/monotonicity/jitter-band), `queue_fairness::weighted_queue_order`/`effective_queue_weights` (permutation, zero-weight-last), `task_duration` (round-trip/sum/totality), `completion_trigger::TriggerCondition::evaluate`/`gate_stored_condition` (totality + gate/evaluate agreement over corrupt stored values), `completion_callback::validate_target_url` (internal IPv4/IPv6 literals never validate even under the permissive policy), `WorkflowEvent` serde round-trip + #521/#488 additive-field back-compat, `build_routing::ramp_bucket`/`validate_ramp_percent`, `dlq::failure_signature` (idempotent fixpoint, `<= SIGNATURE_MAX_LEN`); in-crate proptests for non-public targets `worker::nd_block_backoff` (private, db-gated) and `context::remaining_secs_until` (`pub(crate)`).

**Fuzz harness** (`cargo-fuzz` / libFuzzer, PR #1004): a new `fuzz/` crate **excluded** from the root workspace (root `Cargo.toml` `[workspace] exclude = ["fuzz"]` + its own empty `[workspace]` table), so the root resolver never builds these nightly/libFuzzer-only binaries — verified via `cargo metadata --no-deps` (`autumn-harvest-fuzz` is not a member) and a clean `cargo build -p autumn-harvest --no-default-features` with `fuzz/` present. Four targets over the functions where raw-bytes coverage-guided fuzzing genuinely beats structured proptest: `fuzz_workflow_event_deser` (`serde_json::from_slice::<WorkflowEvent>` totality — every history read path deserializes this append-only enum), `fuzz_det_check_source` (`det_check::check_source` totality — the highest-value target given the historical parity churn against the proc-macro determinism lint; a hand-rolled line/brace scanner run over user code in CI/editors), `fuzz_validate_target_url` (`completion_callback::validate_target_url` totality under the most-permissive SSRF policy — issue #605 security boundary), `fuzz_failure_signature` (`dlq::failure_signature` totality + `<= SIGNATURE_MAX_LEN`; `db`-gated, so the fuzz crate enables the `db` feature). `fuzz/smoke.sh` runs each target ~15s for local/manual use. In-sandbox `cargo +nightly fuzz build` built all four; each ran ~9s clean (hundreds of thousands of executions, zero crashes).

**CI** (`.github/workflows/ci.yml`): (1) a new **"Run db-gated property suites"** step in the existing `test` job (`cargo test -p autumn-harvest --features db --test property`) — `build_routing_props`/`dlq_props` were previously only *compiled* (never executed) by the `--no-run`/`--lib` db steps; they need no Docker. (2) A new opt-in **`fuzz-smoke`** job gated `workflow_dispatch`-only (never push/PR — Actions minutes are tight and fuzzing needs nightly), 30s per target, plus a `workflow_dispatch:` trigger added to `on:`. (3) A fix to a **pre-existing YAML indentation bug** (line 186, 9 spaces vs 8) that made the entire workflow invalid YAML — load-bearing for any of these additions to parse.

**Docs**: `docs/testing/property-and-fuzz.md` — how to run both layers (incl. the db-featured line and `PROPTEST_CASES` deep runs), the target-selection rationale (pure functions / parsers / totality), and a per-subsystem follow-up backlog including the two deferred items **C12** (det_check ↔ macro-guardrail differential — needs a proc-macro test harness since `determinism_lint.rs` isn't an invocable `pub fn`) and **C13** (`WorkflowReplayer`-based replay-determinism property under `--features testing`, reusing the #476 1000-ordering precedent), plus scheduler cron parsing, `resolve_concurrency_key`/`project_json_path`, `throttle::parse_rate`, rendezvous shard-routing stability, and `validate_against_schema`-vs-serde candidates.

**No new `WorkflowEvent` variant, no migration, no route change, no replay/determinism impact, no product-code change** — test/tooling/docs/CI only. Local verification: property suites `21 passed` (no-db) / `26 passed` (db), both sub-second; `cargo fmt --all -- --check` clean.
