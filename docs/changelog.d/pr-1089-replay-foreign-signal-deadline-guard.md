## Phase 3.x — replay: only cross this signal's own deadline timer in `match_signal` (issue #1071)

Follow-up correctness fix on the merged PR #1084 (issue #1071), caught by Codex review. `HistoryMatcher::match_signal`'s interleaved-sibling arm — added by #1084 so a plain `wait_for_signal` tolerates a sibling deadline timer's `TimerFired` recorded before the awaited signal — crossed **any** reserved `__signal_timeout:*` deadline timer *without a rewind*, keyed only on the reserved **prefix** (`signal_timeout_race_name(...).is_some()`). So when a plain `wait_for_signal("a")` runs concurrently with a `receive_signal_timeout("b", …)` in one mixed batch and b's deadline fires before a arrives, the `match_signal("a")` scan advanced the cursor past a **foreign** signal's deadline events (`TimerStarted(__signal_timeout:1:b)` + `TimerFired(...)`) without setting `first_interleaved_command`. The "b" branch's positional `match_signal_or_timer("b")` could then no longer re-anchor on its own `TimerStarted`, so strict replay diverged with `NonDeterminismDetected{EarlyCompletion}` even though both waits genuinely resolved.

**Fix (one-line guard narrowing):** the guard changes from name-agnostic `.is_some()` to name-matched `== Some(signal_name)`, so the cross-without-rewind arm fires **only for THIS signal's own** reserved deadline timer. A foreign-name reserved timer instead falls through to the existing generic `TimerStarted` rewind arm (as does a genuine user `ctx.timer` sibling), which sets `first_interleaved_command` so the sibling race re-anchors and resolves `TimerWon` after the win. Behavior is **byte-identical** for the same-name #1071 case (`interleaved_sibling_signal_after_deadline_timer_fired_replays_succeeded`) — `Some("go") == Some("go")` still matches — and the park-forever guard (`matcher_signal_scan_parks_on_lone_open_deadline_timer`) is untouched. The arm's comment, which described (and over-claimed for) the old name-agnostic behavior, is rewritten to state that it only crosses this signal's own deadline timer and that a foreign one is deliberately left to its own race matcher via the rewind path.

**No new `WorkflowEvent` variant, no migration** — a strictly narrowing change to one replay-matcher arm that diverts foreign-name reserved timers to the existing generic rewind path. Regression test `interleaved_two_signal_race_foreign_deadline_timer_replays_succeeded` (in `autumn-harvest/tests/integration/replayer_tests.rs`) encodes Codex's exact composition (`tokio::join!(wait_for_signal("a"), receive_signal_timeout::<Value>("b", 5s))`, "a" polled first, history `[WorkflowStarted, TimerStarted(__signal_timeout:1:b), TimerFired(__signal_timeout:1:b), SignalReceived(a)]`); it **fails pre-fix** with `NonDeterminismDetected(kind=EarlyCompletion, event_index=4)` and **passes post-fix** with `ReplaySucceeded`. Verified green at the pinned CI toolchain 1.97.0: `cargo fmt --all --check`, `cargo clippy -p autumn-harvest --all-features --tests -- -D warnings`, `cargo test -p autumn-harvest --no-default-features --features testing --test integration` (961 passed), and `cargo test -p autumn-harvest --all-features --lib` (2138 passed).
