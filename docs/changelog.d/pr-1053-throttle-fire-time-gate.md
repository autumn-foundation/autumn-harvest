## Phase 3.51 — Admission-gate hardening: throttle fire-time gate + reuse-policy-aware batch bypass (issue #1053)

Consolidated admission-gate (#377 / #618 / #1014) hardening follow-up split out of PR #1051's review. Two pieces, each carrying its own contract decision.

**(1) Throttle scanner now honors the admission gate at fire time — deliberate contract change.** A deferred throttle start (issue #607) creates no execution at defer time — it persists a `harvest_start_throttle` row and returns `202`. The actual create-vs-attach commits later in the scanner (`throttle::fire_claimed_throttle_row`), which previously called `start_or_load_workflow_execution_collect(..., gate: None)` — gate-exempt by construction (the deliberate #618-F1 `GatedAtAdmission` exemption). **Before:** a throttled start deferred while no gate was armed would fire the instant its tokens refilled, *even if an operator had since armed an admission gate on its scope* — the last deferred-fire leak past an active gate. **After:** the scanner passes `Some(GateMode::CheckCached)` and re-checks the gate on the workflow's real queue immediately before firing. When a gate matches it **blocks and RE-DEFERS** the row: it leaves the `harvest_start_throttle` row in place, **refunds** the token it reserved for the attempt, starts nothing, and counts `harvest.admission.blocked` — so the held start fires the instant the gate opens (or is dropped only if its `schedule_to_start` deadline passes first). **Nothing is lost.** This reverses the #618-F1 exemption: the throttle deferred-start `202` now means *"will run when tokens allow **AND** the admission gate is open at fire time"*, not merely *"will run when tokens allow"* — the correct halt-beats-pace semantics for an operator slamming a gate mid-incident.

**Producer contract flip.** `throttle` moves from `gated_at_admission` to `gated_at_relay` at `GET /admin/gates` (`admission_gate::producer_contract`). It shares the `check_cached` relay-time mechanism with the completion-trigger cross-shard outbox (also `GatedAtRelay`) but **differs in disposition**: the completion-trigger outbox **drops** its row on block (its source terminal decision has already fired, so a permanently gated relay must not accumulate forever); the throttle scanner **re-defers** its row (its `202` "nothing lost" promise). A blocked fire counts `harvest.admission.blocked` and a genuinely-fired start counts `harvest.admission.bypassed{producer="throttle"}` — never both (block-vs-bypass never double-counts). `debounce` and `event_batch` **remain** `gated_at_admission` — #1053 scopes only throttle.

**Coverage.** Closes BOTH (a) the pre-existing looseness where ANY deferred throttle start fires gate-exempt if the gate arms after deferral, and (b) the narrow PR-#1051 residual — an attach-policy bypass whose prior is force-terminated between the unlocked read and the scanner fire, so the deferred fire becomes a fresh CREATE. (b) is a subset of (a): every deferred fire now faces the fire-time gate; force-terminate is merely what turns a would-be attach into a would-be CREATE.

**(2) Batch route reuse-policy-aware bypass (structural / defensive).** The batch-start Phase-1 idempotent-retry pre-check (`autumn-harvest-plugin/src/api.rs`) previously bypassed the admission gate on a bare "any non-sealed prior exists" existence boolean. **After:** it loads the prior's *state* and decides the bypass with `execution::start_will_create_new_execution(prior_state, AllowDuplicate)`, mirroring the single-start route fixed in #1051. **No behavior change today** — the batch route starts every item under `AllowDuplicate` (`BatchStartItem` has no reuse-policy field), so the predicate agrees with the old existence boolean for every prior state — but it stays correct if a per-item reuse policy is ever added, and the throttled batch item's real residual is closed by (1) since a deferred batch item fires through the same `fire_claimed_throttle_row` scanner.

**No new `WorkflowEvent` variant, no migration.** A blocked fire rolls the start transaction back (no row, no events), so there is no replay surface. The metrics recorder is now threaded through `fire_claimed_throttle_row` / `fire_due_on_conn` (mirroring `debounce` / `event_batch`) so the fire-time block is counted on the passed recorder rather than only the process-global fallback. Tests: `throttle_scanner_re_defers_under_a_closed_gate_and_fires_when_open` (money — block+re-defer under a closed gate, fire once open), `throttle_row_deferred_before_gate_is_held_when_gate_arms_before_fire` (coverage (a)), `throttle_deferred_fire_over_a_force_terminated_prior_faces_the_gate` (coverage (b)), `batch_bypass_uses_start_will_create_predicate_not_bare_existence` (structural regression-lock); four existing tests flipped from the old "fires despite the gate" contract to the new fire-time-gate contract.
