## Tooling — Test INIT_SQL bundle migration-drift guard (PR #1031)

**Tooling/testing** (implemented): Test suites build their Postgres schema from hand-maintained `const INIT_SQL = concat!(include_str!(".../migrations/.../up.sql"), ...)` lists. When a migration adds a column to a hub table, a bundle that misses it fails **at runtime** (`column "..." does not exist`) — but `include_str!` compiles fine, and dozens of these suites are **compiled but never executed** in CI, so the drift is invisible until someone runs them locally. This bit CI ≥4 times in one week (latest: `nd_block_tests` missing the #604 build-ramp migration, with no CI run step at all). This slice makes both failure modes hard CI errors going forward, ships a drift-proof shared schema bundle, and fixes the concrete known gaps so they actually run in CI. **No product-code behavior change.**

**Paved path** — `autumn_harvest::full_migrations_sql()` (new, `build.rs`-generated): the complete migration set concatenated in timestamp order, proven to apply cleanly on Postgres 16. New/migrated tests use this instead of a hand-rolled subset, so their schema can never drift.

**Migration-hygiene guard** (`tests/integration/migration_hygiene.rs`, no-DB, every OS): asserts no two migration dirs share a version timestamp (Diesel silently drops one — this bit trunk this week) and that the generated bundle is complete. Replaces a copy that was triple-feature-gated and never ran in CI.

**CI-run-step coverage guard** (`tests/integration/ci_run_coverage.rs`, no-DB, fail-closed): enumerates every db-gated test and asserts each has a Docker-backed run step in `ci.yml` or is on a reason-annotated allowlist. Feature-aware (a `testing+db` suite's step must carry `--features testing`), self-testing (fails loudly if a `ci.yml` reformat breaks the parser), and ratcheted (`ALLOWLIST_MAX_LEN` forbids silent growth). Once a db suite actually runs, Postgres itself catches future column drift — no brittle static analyzer needed.

**Fixed drift + harness bugs** by running suites against a live DB: 4 concrete drift bugs (`nd_block`, `completion_callback`, `worker_session` all missing `build_policy_ramp`; plugin `build_ramp` missing `harvest_audit_log`) each swapped to `full_migrations_sql()`; plus a second, pre-existing nd_block harness bug where 6 tests fired a durable timer but never made the parked task claimable (`make_task_claimable_now` existed but was unused), so the divergent worker never re-claimed it — these tests had never actually executed, now 8/8 green. Docker-backed run steps were wired for `nd_block`, `worker_session`, and plugin `build_ramp` (all verified green on local PG16) and removed from the allowlist.

**Residuals (tracked, not fixed here):** running the never-run suites showed drift is systemic — **73 db-gated suites** (42 core + 31 plugin) are still compiled-but-never-run in CI, now explicitly tracked by the coverage-guard allowlist, each with a reason; most still use hand-rolled bundles. Two genuine non-schema bugs surfaced and were handed off: `completion_callback_tests::scanner_scopes_claims_...shared_pool` (duplicate-key on the active-uniqueness index, test-logic, #605 — kept allowlisted so its run step stays blocked) and `event_batch_tests::size_triggered_flush_threads_completion_callbacks_into_the_started_execution` (a separate pre-existing failure, unmodified here). **Recommended follow-up:** sweep all remaining hand-rolled INIT_SQL bundles onto `full_migrations_sql()`, then progressively wire run steps and shrink the allowlist toward zero — the guards + paved path make that mechanical and block any *new* drift or never-run suite in the meantime.

**No new `WorkflowEvent` variant, no new migration, no route/contract change, no replay/determinism impact, no production-logic change** — test infra only (the nd_block fix is test-harness code). Verification (local CI mirror; DB suites executed on Postgres 16): guards 8/8 in the no-DB CI leg (all OSes); `nd_block` 8/8, `worker_session` 17/17, `build_ramp` 6/6 against live PG16; fmt / clippy (harvest `--all-features --tests`, plugin `--all-targets`, macros) / no-DB tests (95 lib + 823 integration) / `--all-features --tests --no-run` all green.
