## Tooling — Wire 3 previously-never-run DB test suites into CI (PR #1037, follow-up to #1031)

**Tooling/testing** (implemented): PR #1031's CI-run-step coverage guard surfaced that three db-gated core integration suites — `workflow_retry_tests`, `completion_callback_tests`, `event_batch_tests` — compiled in CI but never executed against a live Postgres, hiding **5 test-harness bugs** (not production regressions: each failing test was contradicted by a *passing sibling* encoding the real production contract). This slice fixes all 5, wires the three suites into Docker-backed CI run steps, and removes them from the coverage-guard allowlist. **No product-code behavior change** — every fix corrects a test to assert a TRUE production contract already proven by a passing sibling.

**The 5 fixes** (all in `autumn-harvest/tests/integration/`):

1. `workflow_retry_tests::cancelled_workflow_is_not_retried` — waited for `wait_for_state(exec, &["SUSPENDED"])`, but `"SUSPENDED"` is not a persisted state (a timer-parked run's row is `"RUNNING"` with `worker_id IS NULL`; the state CHECK constraint forbids `"SUSPENDED"`). Fixed: the `timer_wait_handler` timer is lengthened to 3600s so it cannot fire during the poll window, and a new `wait_for_parked` helper polls the `harvest_timers` table for the durable timer row (the unambiguous "parked" signal) instead of an unreachable state string. The cancel + not-retried assertions now actually run.

2. `workflow_retry_tests::workflow_non_retryable_error_no_retry` — the fixture returned `Err("NullPointerException: bad input")` with `non_retryable_errors: ["NullPointerException"]`, but `RetryPolicy::is_non_retryable` matches on **exact equality**, not substring (documented, and proven by passing siblings `workflow_sentinel_string_non_retryable_message_no_retry` and `workflow_typed_non_retryable_error_type_no_retry`). Fixed by converting `non_retryable_fail_handler` to return a **typed** `WorkflowFailure::new("NullPointerException", "NullPointerException: bad input")` (mirroring the passing typed sibling), so the #523 retry gate's typed `error_type` class match fires on exact class equality. The typed form was chosen over a bare exact-string `Err("NullPointerException")` because it faithfully preserves the fixture's intent — exception CLASS as `error_type` + detail as the human message — and matches the passing sibling's shape exactly.

3. `workflow_retry_tests::workflow_retry_exhaustion_counts_as_one_failure` — its final block loaded executions filtered by the ORIGINAL `workflow_id`, but a #523 retry run gets a **distinct UUID `workflow_id`** (the tested contract, per passing `retry_run_has_fresh_history_and_correct_linkage`), so the attempt-2 row was never found and `.expect("attempt 2 must exist")` panicked. Fixed by selecting the retry run via the `retry_of_exec_id` FK — using the file's own `wait_for_retry_state` helper — matching this file's `failed_count` loop.

4. `completion_callback_tests::scanner_scopes_claims_to_the_assigned_shard_when_shards_share_a_pool` — the `insert_terminal_execution` helper hardcoded `(process_refund, wf-1)`; this test inserts two COMPLETED rows, colliding on the partial active-uniqueness index `harvest_we_workflow_name_workflow_id_active_key` (COMPLETED is not excluded). Fixed by parameterizing the helper with a `workflow_id` arg and giving the two execs distinct ids (`wf-0`/`wf-1`); all other callers pass their existing `wf-1` id, so they are unchanged.

5. `event_batch_tests::size_triggered_flush_threads_completion_callbacks_into_the_started_execution` — admitted the SAME callback array on all 3 batch admissions and asserted the stored column equals the single-element array. Production intentionally **concatenates** per admission (issue #921) and dedups only at delivery, so the stored value is `[hook, hook, hook]` (len 3), not `[hook]` — the concatenate-and-merge contract proven by the passing sibling `a_later_admissions_completion_callbacks_are_merged_not_dropped` (two distinct targets → len 2). Fixed the assertion to expect the concatenated union.

**CI wiring + allowlist:** `.github/workflows/ci.yml`'s Docker-backed step for `workflow_retry_tests::workflow_typed` (a `::` sub-filter that masked the other tests) was expanded to run the full `workflow_retry_tests` module, and new Docker-backed run steps were added for `completion_callback_tests` and `event_batch_tests` (matching the file's `-p autumn-harvest --test integration -- <module> --test-threads=1`, `if: runner.os == 'Linux'` convention). The three entries were removed from `ci_run_coverage.rs`'s `ALLOWLIST`, `ALLOWLIST_MAX_LEN` dropped 77 → 74, and the two now-unused reason constants (`ALLOWLIST_WORKFLOW_RETRY_REASON`, `ALLOWLIST_COMPLETION_CALLBACK_REASON`) removed.

**No new `WorkflowEvent` variant, no migration, no route/contract change, no replay/determinism impact, no production-logic change** — test-harness fixes + CI wiring only. Verified against a local Postgres 16: all three suites fully green; plus fmt / clippy (`-p autumn-harvest --all-features --tests -- -D warnings`) / no-DB unit + integration tests / the `ci_run_coverage` guard.
