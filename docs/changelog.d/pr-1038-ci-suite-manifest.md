## CI — manifest-driven integration-suite runner (test-infra)

Replaced the ~35 copy-pasted per-suite `cargo test` steps in `.github/workflows/ci.yml`'s `test` job — 29 Docker-backed run steps, the shared 17-token plugin `--no-run` compile line, the `mcp_tools_integration` compile step, and 5 all-OS target-run steps — with **one parameterized runner** (`.github/ci/run-suites.sh`) reading a **line-oriented, `merge=union`-safe manifest** (`.github/ci/integration-suites.txt`). Adding an integration suite is now **one sorted manifest line** — no `ci.yml` edit, no shared-tail conflict.

**Root cause fixed.** Three shared append-tail regions made any two concurrent suite-adding PRs collide: the per-suite Docker run steps, the one physical plugin `--no-run` line (every new plugin suite appended a `--test` token to it), and the Rust `ALLOWLIST` array. The manifest is `merge=union` (see `.gitattributes`), so two PRs each appending a line both land with **no textual conflict**; a union-merge duplicate/reorder residue is caught deterministically (never a conflict) by `ci_run_coverage.rs::manifest_is_sorted_and_unique`, which prints a one-command `sort -u` fix.

**Manifest schema** (`osclass crate target features filter`, whitespace-columnar, `#`-comment tolerant, `-` = none): `osclass` ∈ `linux` (run serial on Linux against Docker Postgres + compile-checked on every OS) | `allos` (run on all 3 OSes, parallel, no live DB) | `compileonly` (`--no-run` on every OS, never executed). `--test-threads=1` and `--no-run` are **derived from `osclass`** by the runner and never written in the manifest — so the `--test-threads=1`-after-`--`-after-filter ordering is correct by construction (kills the mis-emit class). For `autumn-harvest` `integration` `allos` rows the runner adds `--no-default-features` (strips the crate's `default = ["db", "unified-dag-execution"]`, since `allos` has no Postgres); this reproduces the old `:142`/`:145` commands byte-for-byte while leaving the `property` `allos` row (which keeps `db`+`unified-dag-execution`) unchanged. **Every generated command is byte-faithful to the pre-refactor `ci.yml`.**

**Runner** (`.github/ci/run-suites.sh`, `run <linux|allos>` and `compile` modes) is bash-3.2 / Git-Bash portable (no associative arrays, no `mapfile`; compile-mode batching groups by `(crate, features)` via `sort` + adjacent-run walk). It wraps each suite in `::group::`/`::endgroup::`, **collects failures instead of aborting on the first** (a strict improvement over the old fail-fast leg, which hid every suite after the first failure), and exits non-zero at the end printing every failed suite. `compile` mode regenerates both the shared plugin `--no-run` batch and the `mcp,unified-dag-execution` batch from the manifest, so every `linux`/`compileonly` plugin target is still compile-checked on macOS/Windows.

**Gating preserved exactly.** The 3 replacing steps keep **per-step** `if:` (`allos`/`compile` → `needs.changes.outputs.code == 'true'`; `linux` → `runner.os == 'Linux' && needs.changes.outputs.code == 'true'`) and `shell: bash` — never hoisted to a job-level `if:` on the matrix job (which would strip the leg contexts and hang branch protection). The heterogeneous steps (fmt/clippy, `--lib`, the core blanket `--all-features --tests --no-run` compile, `cargo build --example`, whole-crate and example runs, `cargo clean`) stay hand-written.

**Coverage guard rewrite** (`autumn-harvest/tests/integration/ci_run_coverage.rs`) now derives "which suites have a real CI run" from the **manifest** (structured columns) instead of scraping `ci.yml` `run:` lines: the `--test-threads=1` special-casing, `--no-run` string-grepping, and `module::filter` re-tokenization are deleted. Preserved: the ratcheted `ALLOWLIST` + `ALLOWLIST_MAX_LEN` cap (73 entries / cap 77, unchanged — the covered set is identical), feature-awareness (a `testing`+`db` suite's manifest row must carry `testing`), the plugin dir-scan, the all-`#[ignore]`d handling, and the stale-allowlist check. Added: (i) `ci_yaml_invokes_the_runner_against_the_manifest` (a manifest can't be silently ignored — `ci.yml` must invoke `run-suites.sh {compile, run allos, run linux}` and the script must reference the manifest path), and (ii) `manifest_is_sorted_and_unique` (union-artifact self-heal with a `sort -u` fix message). The guard was proven fail-closed: deleting one `linux` line makes it fail naming that suite and printing the exact manifest line to re-add.

**Adding a suite going forward:** append one sorted line to `.github/ci/integration-suites.txt` (keep the header comment on top; `sort -u` the data lines). No `ci.yml` edit; no `ALLOWLIST` edit for a wired suite. No new `WorkflowEvent` variant, no migration, no runtime-code change — CI infrastructure only.
