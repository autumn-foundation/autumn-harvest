## Phase 3.52 — Durable named cross-workflow mutex — `ctx.mutex` (issue #691)

`WorkflowContext::mutex(key: impl Into<String>) -> MutexHandle`; `handle.acquire().await -> HarvestResult<MutexGuard>` durably suspends the workflow until it holds exclusive access to `key`. The guard is a `#[must_use]` RAII handle that releases the lock on drop / scope exit, explicit `guard.release()`, the holder reaching any terminal state, or the lease TTL expiring. This is the durable, replay-safe answer to "two executions must not read-modify-write the same shared resource at once" — a `#[workflow]` cannot reach for a `std::sync::Mutex` (it would not survive a worker restart, and holding a std lock across a durable `.await` breaks replay). `MutexHandle`/`MutexGuard` are re-exported from `lib.rs` and the prelude. Author-facing primitive only: exclusive-only, no reentrancy/upgrade/downgrade, and no operator force-release route (all out of scope per the issue).

**Preempts "duplicate of per-key concurrency (#247)?":** concurrency gates **admission** at workflow *start* and caps the running *count* of whole workflows sharing a key (`limit = 1` serializes the entire workflow and risks parent/child deadlock); `ctx.mutex` gates a **region** *mid-workflow*, so only the critical section serializes and the rest of each workflow runs concurrently with peers.

**Append-only, single-event design.** A grant records exactly **one** new `WorkflowEvent` tail variant, `MutexGranted { key, lock_seq, acquired_at }` (the replay anchor); release is **event-less** bookkeeping (a `ReleaseMutex` command, mirroring `SetCurrentDetails`) — a release *event* would need adding to every forward-scan skip-list, so it is deliberately avoided. `HistoryMatcher::match_mutex_granted(key)` is **positional** (mirrors `match_timer_arm`), so no other scan's skip-list changes. Acquire is a **solo durable suspension** (its batch cannot co-contain an activity/timer/child/signal command — a mixed batch fails loud), which guarantees `MutexGranted` lands at a clean resume cursor. Replay recovers the guard from the recorded grant regardless of which fencing token (`lock_seq`) was minted (a 1000-cycle varying-`lock_seq` replayer fixture pins this).

**FIFO fairness.** Contenders are granted in arrival order via a BIGSERIAL head-of-line waiter queue (`harvest_mutex_waiters`): a grant goes only to the head-of-line waiter; `enqueue ON CONFLICT DO NOTHING` preserves the original FIFO position across re-parks; a spurious non-head wake just re-parks.

**Lease-based crash safety.** A held lock (`harvest_mutex_locks`) carries a `lease_expires_at` + a `lock_seq` fencing token. Holder decision cycles renew the lease; a lease scanner folded into `timeout::enforce_timeouts_once` reclaims an expired lease and wakes the next FIFO waiter. release/reclaim are fenced on `(holder_exec_id, lock_seq)`, so a reclaimed-then-resumed old holder's release is a 0-row no-op — the lock table never corrupts. Every acquire/release/reclaim/sweep transaction takes `pg_advisory_xact_lock(hashtext(key))` **first** (advisory-first is load-bearing to avoid an ABBA inversion between the scanner and acquire). Honest lease contract: the TTL (default 60 s; `WorkerConfig::with_mutex_lease_ttl`) must exceed the worst-case single held step; `lock_seq` fences the lock table but the engine cannot fence the author's *external* side effects (standard lease-lock caveat). A PAUSED holder (#383) is skipped by the reclaim scanner so pausing a holder cannot break mutual exclusion.

**Terminal auto-release.** `sweep_terminal_holder_and_wake` (release-all + delete-waiters + wake-next) is folded into the single terminal chokepoint `completion_trigger::evaluate_triggers_for_execution`, covering complete/fail/cancel/terminate/timeout/poison-pill; continue-as-new sweeps explicitly. A non-terminal ND-block (#603) correctly does *not* sweep. All mutex-table access from cross-suite paths is `to_regclass('harvest_mutex_locks')`-guarded and no-ops when the table is absent, so the migration is **not** added to the hand-rolled test INIT_SQL bundles. Reset of a source that still holds a mutex is **rejected** (`WorkflowResetError::HolderHoldsMutex` → 409) rather than forking a phantom grant.

**Shard-local scope.** The lock, the FIFO queue, and the advisory serialization all live on the workflow's own shard — same scope as per-key concurrency (#247): contending workflows must resolve to the **same** shard. Cross-shard global mutual exclusion is out of scope (documented in `docs/sharding.md`).

**Non-reentrant.** Re-acquiring a key this execution already holds returns `HarvestError::MutexSelfDeadlock` **synchronously** (checked *before* any history match), so a self-deadlock surfaces the same typed error live and on replay rather than hanging.

**Migration** `20260714000001_harvest_mutex_locks`: `harvest_mutex_locks` (lock table), `harvest_mutex_waiters` (BIGSERIAL FIFO queue), `harvest_mutex_lock_seq` sequence. **No other migration.**

**Metrics** (issue #691; `workflow` is the **only** label — the lock key is high-cardinality tenant/entity input and is deliberately *not* a metric label per ADR-0001 §7; `execution.id` stays span-only): `harvest.mutex.wait_duration` (histogram — request→grant wait), `harvest.mutex.held_duration` (histogram — grant→release), `harvest.mutex.contention_depth` (gauge — FIFO waiter-queue length at grant). All three are bridged in `metrics_rs_adapter`, catalogued in `docs/telemetry.md` and ADR-0001 §7, and paneled in `docs/dashboards/starter-pack-v0.1.0.json` (Durable mutex row).

**Tests.** No-DB: `WorkflowTestEnv` acquire/contended/self-deadlock paths and `WorkflowReplayer` fixtures (grant replay, 1000 varying-`lock_seq` cycles, release-before-subsequent-event, key-divergence → `NonDeterminismKind::MutexGrantMismatch`, self-deadlock-checked-before-positional-match). DB (`tests/integration/mutex_tests.rs`, driving a real `Worker::run` vs Postgres): mutual-exclusion-under-contention (0 violations via a witness `critical_section` activity asserting max in-flight == 1), FIFO grant order, holder-crash lease reclaim, held-across-suspension-stays-held (the crux), terminal auto-release, cancelled holder/waiter cleanup, self-deadlock, release-on-guard-drop-grants-next, paused-holder-lease-not-reclaimed, reset-rejected-while-holding + reset-after-release-succeeds, co-batch-fail-loud, early-release-before-terminal. Example `autumn-harvest/examples/mutex_ledger.rs` (two workflows serialize read-modify-write to the same per-account balance) with 2 embedded `WorkflowTestEnv` tests.
