# Upgrading from 0.9.0 to 0.10.0

This guide covers the move from `0.9.0` to `0.10.0`. Section 1 lists the
breaking and behavior changes. Section 2 lists the migrations. Section 3
lists the rules for a rolling deploy of the new features. Section 4 lists
the new opt-in features. Section 5 lists the dependency changes.

`autumn-web` moves from 0.9 to 0.10. The MSRV moves from 1.88.0 to 1.97.0.

Do the steps in this order:

1. Read section 1 and fix each change that affects you. Sections 1.3 and
   1.4 change where a `web` replica runs work, so read them before the roll.
2. Bump the Harvest crates and `autumn-web` in one change, as section 5.1
   shows.
3. Run `cargo check`, then your tests.
4. Run the migrations in section 2, then deploy.
5. Turn on a new feature only after every process runs `0.10.0`. See
   section 3.

---

## 1. Breaking and behavior changes

### 1.1 `autumn-web` 0.10 — BREAKING

**What changed (issue #2479).** `autumn-harvest-plugin` now depends on
`autumn-web` 0.10, which adds named roles (autumn#3543). The public API of
the plugin holds `autumn-web` types. Cargo treats 0.9 and 0.10 as different
crates.

**Who is affected.** Every app that mounts `HarvestPlugin`, and every app
that names `autumn-web` in its own manifest.

**What to do.**

1. Bump your own `autumn-web` entry to `"0.10"`. A leftover `"0.9"` builds
   two copies, and `HarvestPlugin` does not match the `AppBuilder` of the app.
2. Check that `cargo tree -i autumn-web` shows one version.
3. If you set `[roles.<name>] mount`, name the `harvest` route group in it.
   Each Harvest route is in that group. `HarvestPlugin::route_group()`
   returns the name.

The plugin follows two `autumn-web` API changes. `AppState::role()` now
returns a `Role`, and Harvest reads its `base()`. `Route` has a new `group`
field.

### 1.2 The MSRV is 1.97.0 — BREAKING

**What changed (PR #2523).** `wasmtime` 50 needs Rust 1.97, so the MSRV
moves from 1.88.0 to 1.97.0. A checkout of this repository still builds
with the release pinned in `rust-toolchain.toml`.

**What to do.** Build with Rust 1.97.0 or newer.

### 1.3 A `web` replica runs no worker and no scheduler — BEHAVIOR CHANGE

**What changed (issue #2477).** The Harvest worker and scheduler switches
now follow the Autumn process role. An `AUTUMN_ROLE=web` replica no longer
runs the Harvest worker or scheduler. It still serves the management API
and starts workflows. A `worker` or `combined` role runs both. A runtime
with no `AppState`, such as a standalone runner, has no role and keeps
`true`.

`HarvestRuntimeConfig::worker_enabled` and `scheduler_enabled` are now
`Option<bool>`. `None` is the default and follows the role. An explicit
value wins. A value against the role logs one `warn!` per switch.

**Who is affected.**

- A fleet with only `web` replicas. It then claims no task.
- Code that builds `HarvestRuntimeConfig` with `worker_enabled: true` or
  `scheduler_enabled: true`. That no longer compiles.
- An old API replica with `WORKER_ENABLED=false` and no `AUTUMN_ROLE`. It
  has the `combined` role, so it now logs a warning.

**What to do.**

1. Before the roll, add `worker` replicas, or set
   `AUTUMN_HARVEST__WORKER_ENABLED=true` and
   `AUTUMN_HARVEST__SCHEDULER_ENABLED=true` on the `web` replicas.
2. In a struct literal, write `Some(true)`, or leave the field unset.
3. On an API-only replica, set `AUTUMN_ROLE=web` in place of
   `WORKER_ENABLED=false`.

The SQLite backend always runs its driver. The `web` role does not stop
it. See [Process roles](../operations/process-roles.md).

### 1.4 The retention janitor runs where the scheduler runs — BEHAVIOR CHANGE

**What changed (issue #2478).** The retention janitor now runs where the
scheduler runs. A `web` replica runs no scheduler, so it runs no retention
sweep. An explicit `scheduler_enabled` moves retention with it.

- `POST /admin/retention/run-now` on a process with no placed janitor
  returns `503`. The message names `run_on = "all"`. On a split fleet the
  `web` replicas serve the API, so `harvest retention run-now` returns
  `503` there by default.
- `GET /admin/retention` on such a process adds `placed_elsewhere: true`.
  An empty `per_shard` then means "not here", not "idle".

**Who is affected.** A fleet whose retention ran on `web` replicas, and a
script that calls `run-now` through a `web` replica.

**What to do.** Keep a `worker` or `combined` replica in the fleet. To keep
the old behavior, set `[harvest.retention] run_on = "all"` or
`AUTUMN_HARVEST_RETENTION__RUN_ON=all`. The SQLite backend ignores
`run_on`.

### 1.5 New `HarvestRuntimeConfig` fields — BREAKING for a struct literal

**What changed (issues #2478 and #2479).** `HarvestRuntimeConfig` gains
`retention`, a `HarvestRetentionConfig`, and `worker`, a
`HarvestWorkerConfig`. `[harvest.worker] queues` narrows the queues that
the worker of one process polls. With no list, the `pin` of a named Autumn
role narrows it. An undeclared queue stops the boot.

**Who is affected.** Code that builds `HarvestRuntimeConfig` with a struct
literal and no `..Default::default()`.

**What to do.** Add `retention: Default::default()` and
`worker: Default::default()`, or end the literal with
`..Default::default()`.

`GET /admin/config` now reports `worker.queues` as the polled list. The new
`worker.declared_queues` holds the declared list. `GET
/admin/queue-coverage` adds `unpolled_declared_queues`.

### 1.6 Certificate trust and cron parsing — BEHAVIOR CHANGE

**What changed (PR #2523).** The dependency update changes four behaviors.

- **Certificate trust.** `reqwest` 0.13 uses the OS trust store. It no
  longer uses the bundled Mozilla roots. An image with no CA certificates
  now fails TLS. A private CA in the OS store is now trusted.
- **Cron at the end of DST.** An hourly or shorter schedule in a time zone
  now also fires in the repeated hour. A fixed daily job still fires once.
- **Cron parsing.** `0 0 LW * *` and 7-field expressions with a year now
  parse. An expression with a `+` prefix, such as `+0 0 * * *`, no longer
  parses. Such a stored schedule stops firing.
- **Seeded simulations.** `random_range` draws through `StdRng`, so a
  simulation seed can give a different value. Replay reads the recorded
  value, so replay is not affected.

**What to do.**

1. Install CA certificates in each image. The distroless worker image
   already holds them.
2. Before the upgrade, look for a stored cron expression with a `+` prefix.
   Remove the prefix.
3. An embedder that calls `random_range` with a custom `SampleUniform` type
   implements the `rand` 0.10 trait.

### 1.7 More start paths take the run defaults — BEHAVIOR CHANGE

**What changed (issues #2406 and #2511).** These start paths set no chain
cap, or no execution timeout, before this release. They now take the
declared value of the type, the operator override and the fleet ceilings:

- the outbox start, the Vantage trigger-now of a workflow schedule and the
  typed `signal_with_start` stub (issue #2406);
- each completion-trigger target start, in process, from the immediate
  relay and from the outbox sweep (issue #2511);
- the typed `update_with_start` stub (issue #2511).

A child spawn now caps its chain cap with the fleet chain ceiling.

**Who is affected.** A deployment that uses one of these paths and that
declares `execution_timeout` or `chain_execution_timeout`, or sets
`max_workflow_chain_timeout`. Those runs now get a deadline, or a shorter
one.

**What to do.** Check that the declared timeouts suit the runs that these
paths start.

### 1.8 One consolidation schedule for every agent — BREAKING

**What changed (issue #2540).** The engine keys a schedule by its workflow
name. So the old `consolidate::schedule(when, &agent)` served one agent per
deployment, and a second schedule replaced the first. Now
`consolidate::schedule(when, &ConsolidateAll)` builds one schedule of the
new workflow `agent_consolidate_all`. The per-agent form is gone.

`ConsolidateTask` gets `dispatched` and is now `#[non_exhaustive]`. Build it
with `ConsolidateTask::new`.

**What to do.**

1. Delete a stored per-agent schedule of `agent_consolidate`.
2. Install a directory with `AgentHarness::directory`:
   `postgres::Directory` or `sqlite::Directory`. With none, the read fails
   as `AgentDirectoryMissing`.
3. A worker with a hand-picked activity list adds `agent_consolidate_due`,
   and the workflow `agent_consolidate_all`.

### 1.9 New public fields, variants and arguments

Each item below breaks a struct literal, an exhaustive `match` or a call.
Add each new field to each struct literal, add an arm for each new variant,
or pass the new argument.

**`autumn-harvest`:**

- `ForkEffects` adds `LiveQuiet` (issue #2378).
  `fork_workflow_execution_with_codecs` is new.
- `StartWorkflowParams` adds `workflow_retry_source` (issue #2409).
- `WorkflowMetadata` adds `execution_timeout` and `chain_execution_timeout`
  (issue #2511).
- `HandlerRegistry::with_max_workflow_chain_timeout` and
  `with_max_workflow_execution_timeout` are no longer `const fn` (issue
  #2511).
- `WorkflowEvent::payload_slot_mut` is gone (issue #2499).
  `PayloadCodecs::encode_event_owned` is new.

**`autumn-harvest-plugin`:**

- `HarvestRuntimeConfig` adds `retention` and `worker`. `worker_enabled`
  and `scheduler_enabled` are `Option<bool>`. See sections 1.3 to 1.5.
- `SwitchSource` and `RetentionRunOn` are `#[non_exhaustive]`.

**`autumn-harvest-agent`:**

- `AgentTask`, `ModelTurnRequest` and `ToolCallRequest` add
  `allowed_effects` (issue #2439). Use `None` for the old behavior.
- `AgentTask` and `AgentOp` fail to decode when they carry a key of
  `sampling::SAMPLING_POLICY_FIELDS`, such as `max_draws` (issue #2439).
- `AgentTask` adds `probe`, and `ToolCallRequest` adds `probe_effects`
  (issue #2378). `EvalError` adds `Unsupported` and `Fork`.
- `AgentTask` adds `answer_check` and `kind` (issues #2442 and #2380).
- `ModelTurn` adds `cost_usd_micros: Option<u64>`, and `AgentReport` adds
  `cost_usd_micros: u64` (issue #2443). A turn that an older worker ran
  records no cost, so a cost total reads low during a mixed roll.
- `AgentReport` adds `answer_rejections`, and `AgentStop` adds
  `AnswerRejected` (issue #2442). A decoder from `0.9.0` cannot read
  `answer_rejected`.
- `Peer` adds `answer_limit` (issue #2481). A struct literal needs
  `..Peer::new(..)`. `DelegationRecord` adds `answer_truncated` and
  `serial` (issues #2481 and #2483).
- `Evaluation` and `AnonymisedEvaluation` add `recorded_verdict`,
  `candidate_verdict` and `scorer_usage` (issue #2447). `Evaluation` also
  adds `candidate_usage` and `candidate_cost_usd_micros` (issue #2380).
- `ProfileOverlayStore::activate` takes an actor, a `Provenance`, as its
  last argument (issue #2374). A store also implements `last_activation`,
  `rollback`, `policy`, `set_policy`, `reset_policy`, `policy_log` and
  `auto_adopt` (issues #2374 and #2394). The raw log functions take a
  `MoveRequest`.
- `OverlayValidator::validate` takes the refine policy. `Provenance` adds
  `Auto` (issue #2394). `put`, `activate` and `rollback` refuse an `auto`
  actor. `ProposeRequest` refuses an unknown key.
- `ConsolidateTask` is `#[non_exhaustive]` (issue #2540).

Each new serialized field has a serde default and is skipped when empty.
So a recorded history keeps its bytes.

### 1.10 An evaluation candidate refuses an unknown model route — BEHAVIOR CHANGE

**What changed (issue #2376).** A `Candidate::agent_model` route to a model
that the harness does not hold now gives `OverlayError::UnknownModel`
before any call. A new `eval_` call id no longer holds the provider id.
Two candidates with equal digests give `EvalError::DuplicateCandidate`
before any model call.

**What to do.** Give each candidate a model that the harness holds, and a
distinct `Candidate::label` when two candidates are otherwise equal.

### 1.11 The shortest OIDC session age is two seconds — BEHAVIOR CHANGE

**What changed.** `OidcLogin::with_max_session_age` raises an age under two
seconds to two seconds. The login time has a one-second resolution, so a
one-second session could expire at the next clock tick. No production
setting is this short, so no action is needed.

### 1.12 SQLite backend changes — NO ACTION

The SQLite backend changes its file on open. No step is needed.

- `harvest_events` gains a `recorded_at` column (issue #2489). The
  `INSERT` writes it, so the append-only guard is unchanged. Replay does
  not read it.
- `harvest_schedules` gains `pause_reason` (issue #2471).
- `harvest_workflow_logs` is a new table (issue #2468).
- Each `SqliteRuntime` transaction now begins `IMMEDIATE` (issue #2469).
  The runtime and the auth store then wait on the busy timeout, and
  neither fails with `SQLITE_BUSY`.

## 2. Migrations

`0.10.0` adds seven Postgres migrations. Each one adds a new table, or
nullable columns on the small `harvest_run_default_overrides` table. None
rewrites `harvest_events`. Each one sets `lock_timeout` to 5 s. If it
fires, run the migration again. See [the migration table](0.5.0.md) for
each row.

### 2.1 An operator sampling policy for agent kinds — RUN THE MIGRATION

Issue #2439 adds `SamplingPolicy` to `autumn-harvest-agent`. An operator
sets it per agent kind through `harvest agents sampling policy`. The new
workflow `agent_draws` reads it once per strategy run.

**Who is affected.** Nobody at once. A kind with no policy reads every
default, and the defaults allow no strategy.

**What to do.** Run migration `20261102032158_harvest_agent_policies`. It
creates two new tables. It takes no lock on a hot table. A role that reads
a policy needs `SELECT` on `harvest_agent_policies` and
`harvest_agent_policy_audit`. A role that sets one also needs `INSERT` and
`UPDATE` on `harvest_agent_policies`, `INSERT` on
`harvest_agent_policy_audit` and `USAGE` on its sequence. `GET
/admin/preflight` checks these grants.

### 2.2 Operate agent profile overlays — RUN THE MIGRATION

Issue #2374 adds the `/agents/{kind}/profile` routes and
`harvest agents profile`. Each store logs each move of the pointer, and
`rollback` reverses the last move.

**Who is affected.** An app that installs an overlay store. A Postgres
store needs the new table. A custom store implements the new methods of
section 1.9.

**What to do.** Run migration
`20261102142302_harvest_agent_overlay_activations`. It creates one new
table and a trigger. It takes no lock on a hot table. A role that runs the
store needs `SELECT` and `INSERT` on `harvest_agent_overlay_activations`.
Install the store on the plugin with `HarvestPlugin::agent_overlay_store`.
The SQLite plugin refuses that call for now (epic #2466).

### 2.3 The operator refine policy — RUN THE MIGRATION

Issue #2394 adds a refine policy for each agent kind, the
`/agents/{kind}/profile/policy` routes and
`harvest agents profile policy`. A kind with no policy uses every
default. The defaults never adopt an overlay.

**Who is affected.** An app that installs an overlay store, or writes its
own store or validator. See section 1.9.

**What to do.** Run migration
`20261103134706_harvest_agent_refine_policies`. It creates one new table
and a trigger, and widens the author kind `CHECK` of
`harvest_agent_overlays` and `harvest_agent_overlay_activations`. It takes
no lock on a hot table. A role that runs the store needs `SELECT` and
`INSERT` on `harvest_agent_refine_policies`.

### 2.4 Runtime overrides of four more run defaults — RUN THE MIGRATIONS

`PATCH /admin/workflow-types/{workflow_name}/run-defaults` takes four more
groups of fields. Each one has the tri-state, the audit row and the cache of
the existing run-default fields. `GET` shows each one in `code`, `override`
and `effective`. See [Run-default overrides](../operations/run-default-overrides.md).

| Migration | Fields | Issue | When a change applies |
|---|---|---|---|
| `20261102141324_harvest_run_default_chain_timeout` | `chain_execution_timeout_secs` | #2406 | The next chain that starts. A chain in flight keeps its deadline. |
| `20261104173743_harvest_run_default_concurrency_limit` | `concurrency_limit` | #2407 | A lower limit applies to the next start. A higher limit raises the cap of each live task row of the type. |
| `20261105015009_harvest_run_default_quota_limits` | `quota_max_active_executions`, `quota_max_history_bytes`, `quota_max_dead_letters` | #2408 | The next admission. A run in flight continues. |
| `20261105062317_harvest_run_default_retry_policy` | `retry_max_attempts`, `retry_initial_interval_ms`, `retry_max_interval_ms` | #2409 | The next failure of any run of the type. A schedule's own `retry_policy` still wins. |

**Who is affected.** Nobody at once. A type with no override keeps its code
values.

**What to do.** Run the four migrations. Each one adds nullable columns to
`harvest_run_default_overrides` and widens its row check. The table is
small, and `lock_timeout` bounds its brief lock. No grant changes.

`GET /admin/concurrency` adds `code_limit`, `override_limit` and
`effective_limit` per workflow type. `GET /admin/quotas` now reports the
effective caps in `limits`, and adds `code_limits`, `override`,
`workflow_types` and `override_source`.

A schedule's own retry policy now carries the key
`_harvest_retry_source: "schedule"` in the stored JSON. An older binary
ignores the key.

**Rollback.** Deploy `0.9.0` first, then run a `down.sql`, because `0.10.0`
reads the new columns. The retry `down.sql` deletes each override row that
sets only retry fields.

## 3. Rolling deploy: turn on new features after the roll

The [rolling-deploy contract](README.md) lets `0.9.0` and `0.10.0`
processes run together. A `0.9.0` process does not know the new fields,
activities and markers. It refuses a field that it does not know, cannot
replay a history that holds a new activity, or drops a field. So turn on
each feature below only after every process runs `0.10.0`.

| Feature | Turn it on with | What an old process does |
|---|---|---|
| Run-default overrides (issues #2406 to #2409) | A `PATCH` that sets a new field | Refuses the field with a `400`, and starts or retries runs with the code values. If it clears the last other field of a row, it deletes the row |
| Sampling policy (issue #2439) | `AgentHarness::sampling_policies`, then a policy with `strategies` | Does not register `agent_draws`. It drops `allowed_effects` from a draw, so it runs an `internal` tool that the policy refuses |
| Sample run (issue #2443) | `agent_sample` or `sqlite::start_sample` | Does not register `agent_sample` or `agent_sample_score` |
| Answer check (issue #2442) | `AgentTask::answer_check` | Ignores the field, and cannot decode the `answer_rejected` stop |
| Refine policy read (issue #2394) | `read_refine_policy` in a refine workflow | Does not register `agent_refine_policy` |
| Refine run (issue #2380) | `agent_refine` or `sqlite::start_refine` | Does not register the workflow or its steps. It cannot decode a `ProposeRequest` with a `sample` above 1 |
| Live probe (issue #2378) | `eval::live_probe` | Cannot decode the `live_quiet` fork marker, so it cannot run the probe |
| Episode log (issue #2454) | `AgentProfile::episodes` | Does not register `agent_episode_append` or the consolidation activities |
| Consolidation dispatch (issue #2540) | `consolidate::schedule(when, &ConsolidateAll)` | Does not register `agent_consolidate_all` or `agent_consolidate_due` |
| Worker queue narrowing (issue #2479) | `[harvest.worker] queues` | Ignores the `[harvest.worker]` table, so it polls every declared queue |

`activities()`, `workflows()` and `autumn_harvest_agent::sqlite::register`
add the new activities and workflows. A worker that builds its own list
must add them too.

A delegation answer now uses the harness limit (issue #2481).
`agent_discover_peers` records the limit on each `Peer`, so replay cuts each
answer as the live run did. A lookup recorded before this release has no
limit, so that run keeps the old cut. No action is needed.

## 4. New opt-in features — NO ACTION

Each feature below is off until you turn it on.

- **`HarvestPlugin` on SQLite, slices 2 to 6 (epic #2466).** The SQLite
  plugin now serves the read routes and Vantage (issue #2468), API tokens,
  roles, OIDC and audit (issue #2469), the transactional outbox (issue
  #2470), and schedules, retention, MCP, webhooks and connectors (issue
  #2471). It runs in split and external mode, and with one Harvest file per
  fleet tenant (issue #2472). Its routes keep the Postgres wire contract
  (issue #2489). See [HarvestPlugin on SQLite](../sqlite-plugin.md).
- **`HarvestPlugin::workflow_schedule` (issue #2471).** It adds a code
  schedule on both backends.
- **Runtime run-default overrides (issues #2406 to #2409).** See section
  2.4.
- **Agent profile operations (issues #2374 and #2394).** List, show, diff,
  activate and roll back an overlay version, and set the refine policy of a
  kind. See [the agent adapter guide](../agent-adapter.md), section 18.
- **Sampling (issues #2439, #2442 and #2443).** An operator sampling policy,
  an answer check in the agent loop, and best-of-N and rejection sampling.
  See [the agent adapter guide](../agent-adapter.md), sections 19 to 21.
- **The refine loop (epic #2369).** The `agent_refine` workflow (issue
  #2380), the probe evidence bundle (issue #2377), anonymised comparison
  reports (issue #2376), the live probe on a fork (issue #2378) and scored
  evaluations (issue #2447). See
  [the agent adapter guide](../agent-adapter.md), section 22.
- **Agent memory (issues #2454, #2455 and #2540).** An episode log and a
  consolidation pass, one consolidation schedule for many agents, and the
  long-horizon `recall` eval.
- **Agent helpers for Postgres.** The `postgres` module of
  `autumn-harvest-agent` mirrors its `sqlite` module. See
  [the agent adapter guide](../agent-adapter.md), section 3.
- **History shape fingerprints.** `autumn_harvest::history_shape` returns a
  type histogram, a stable fingerprint and the first divergence of two
  histories.

## 5. Dependency changes

### 5.1 Bump the Harvest crates and `autumn-web` — REQUIRED

Bump every Harvest crate and `autumn-web` in one change.

```toml
[dependencies]
autumn-harvest = { version = "0.10", features = ["db"] }
autumn-harvest-plugin = "0.10"
autumn-web = "0.10"
```

`harvest new` writes these versions.

### 5.2 `reqwest` builds with no default crypto provider — NO ACTION

`reqwest` 0.13 builds with `rustls-no-provider`, so `aws-lc-rs` stays out of
the default build. `autumn_harvest_plugin::http::client_builder` installs
`ring` if the process has no provider. An app that installs its own
provider keeps it.

### 5.3 Other dependency moves — NO ACTION

- `foldhash` is now a non-optional dependency of `autumn-harvest` (the
  awaitables history index).
- `fs4` is gone. `std::fs::File::try_lock` replaces it.
- `HVG002` and `DET002` now also flag the `rand` 0.10 names: `rand::rng`,
  `SysRng`, `random`, `random_range`, `random_bool` and `random_ratio`.
